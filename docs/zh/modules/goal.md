# Goal

[文档索引](../index.md)

目标（goal）是主会话的持久任务。目标处于活动状态时，本套件会在每轮结束后让模型继续，直到模型完成目标、报告阻塞，或由你暂停。开关：`modules.goal`。显示：`goal.display`。

每个主会话有一个当前目标，由该会话树的所有分支共享。新建或 fork 的会话没有目标。子代理不继承目标。

## 命令

| 命令 | 效果 |
| --- | --- |
| `/goal <目标>` | 建立目标并开始工作。替换未完成的目标时会请求确认。 |
| `/goal --tokens 100k <目标>` | 建立带 token 预算的目标，支持 `k` 和 `m` 后缀。 |
| `/goal` 或 `/goal status` | 显示完整目标文本、状态、原因、ID、用量、轮数、有效时长、进度和错误。 |
| `/goal edit <文本>` | 修改目标文本。为旧文本运行的轮次会被中止。 |
| `/goal edit --tokens 200k` | 修改预算。预算耗尽时先提高预算，再执行 `/goal resume`。 |
| `/goal pause` | 暂停，并取消待执行的续跑和等待。进度、用量和证据保留。 |
| `/goal resume` | 恢复未完成的目标。Pi 忙碌时显示 `Goal resumed · waiting`，空闲后继续。 |
| `/goal clear` | 清除目标。 |

目标文本最长 4000 个字符；需求更长时可以引用文件。预算统计 provider 报告的总 token 数，包括输入、输出和缓存 token。不带 `--tokens` 时没有上限。

## 状态

目标存储为 `active`、`paused` 或 `completed`，状态显示分为四种：

| 显示 | 含义 |
| --- | --- |
| `🎯 goal 03:27` | 进行中：模型正在工作，或已安排续跑。 |
| `⏳ goal` | 等待你、等待外部工作（`goal_wait`），或等待 Pi 完成重试或压缩。 |
| `⏸ goal` | 已暂停，原因可用 `/goal` 查看。 |
| `✅ goal` | 已完成，显示 5 秒。 |

时间只统计有效工作时间，等待和暂停的时间不计入。

## 暂停与恢复

暂停只停止自动续跑。无论什么原因，你发来的每条消息模型都会照常处理，可以使用全部工具，只是这一轮结束后不会自行继续。如果所有要求都已验证，模型可以在这一轮完成目标。

你的下一条消息是否同时恢复自动续跑，取决于暂停原因：

| 原因 | 你的下一条消息 | `/goal resume` |
| --- | --- | --- |
| 在编辑器中按 Esc、`ask_user` 被取消、压缩失败或取消 | 恢复自动续跑。 | 恢复。 |
| `goal_blocked`、重试后最终请求失败、自动停跑（见下文） | 恢复自动续跑。 | 恢复。 |
| `/goal pause` | 照常处理，目标保持暂停。 | 恢复。 |
| 预算耗尽 | 照常处理，目标保持暂停。 | 需先提高预算。 |
| 退出 Pi，或 Pi 冷启动 | 照常处理，目标保持暂停。新的 Pi 进程从不自行继续目标。 | 恢复。 |

后台通知、`/reload`、树切换和压缩都不会恢复暂停的目标。目标暂停期间通知照常送达，模型在不带目标工具的一轮中处理它们。例外是因为你取消了询问而暂停的目标：这时通知会等到你发出下一条消息时一起送达。

**自动停跑。** 如果连续 5 个自动轮没有工具调用，或工具调用与结果完全重复，目标以 `no_tools` 或 `repeated_tools` 原因暂停。这是防止死循环的保护，不评判工作质量。你的下一条消息会恢复自动续跑并重新计数。

`ask_user` 被跳过或超时时，目标保持运行。这两种结果都不代表你的同意。

## 模型工具

模型会在目标上下文中收到准确的 `goalId`，并必须把它传给这些工具。

| 工具 | 用途 |
| --- | --- |
| `goal_complete(goalId, summary)` | 标记目标完成。`summary` 必须逐项审计每条要求并给出验证证据。重复完成无副作用，保留第一次的证据。 |
| `goal_blocked(goalId, reason, evidence, repeatedTurns)` | 同一外部障碍连续至少 3 轮出现时暂停目标。未完成的工作不算阻塞。 |
| `goal_wait(goalId, reason, waitFor?, resumeAfterMs?)` | 等待模型已经启动的工作。`waitFor` 列出 1–50 个 `job_`/`agent_`/`wf_` ID，全部结束时目标恢复。可选的 `resumeAfterMs` 期限（1–2147483647 毫秒）到达、所列 job 的监视器事件或 hands-free 更新、任一直接子代理提问，或你发送消息，也会恢复目标。不带 `waitFor` 时，任何通知都会恢复目标。 |

工具错误：参数为空时为 `INVALID_ARGS`，`goalId` 未知时为 `NOT_FOUND`，目标未在自动续跑时调用 `goal_wait` 或 `goal_blocked` 为 `NOT_RUNNING`，目标已被编辑或替换、或本轮不再拥有该目标时为 `STALE_BINDING`。

## 状态显示

`goal.display: "status"`（默认）时摘要显示在 footer 状态中；`dock` 时显示在 Dock 中；`hidden` 时不显示。`/goal` 打开详情视图，使用通用阅读按键（滚动、`/` 搜索、`n`/`N`、Esc）。

## 上下文占用

目标文本和执行规则在每个目标修订版本中只以会话消息的形式加入对话一次。只有状态、预算或模型可用的目标工具变化时才追加简短的控制消息。用量、轮数和进度保存在本套件的状态中，不会复制进每次请求，因此请求前缀在各轮之间保持稳定。
