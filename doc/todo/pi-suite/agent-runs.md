# 子代理运行记录与手动控制

目标：查看活动和已结束的 subagent，保留结果及原生会话历史，并允许用户停止指定 subagent 的当前执行。

当前状态：待实施；上游已有结果读取、持久记录与手动停止，本包需要保留这些能力并接入统一界面。

影响范围：AgentManager、Pi child session、持久结果引用、agents 列表/查看器、停止信号及状态栏数量。

约束：agent 会话与一次执行分开；查看历史不启动模型；停止使用真实运行句柄并保留已产生内容。

相关当前文档：[项目当前状态](../../current/index.md)。

- [ ] 保留运行结果、起止时间、耗时、错误与 child session 引用
- [ ] 对已结束记录复用原生会话查看器，按需读取历史
- [ ] 将手动停止接入 child 的 abort 与工具取消、等待最终结算

- [ ] 将活动数量提供给共享状态栏发布器

## 验收方式

核对运行中、排队、成功、失败、手动停止和恢复后再次运行的记录；完成后读取结果并打开会话，查看不会产生模型请求。停止目标 child，不停止主 agent；嵌套执行取消、关联独立 job 保留、重复 stop 与停止/自然完成竞争均按边界结算。reload 后仍可从持久引用查看已结束结果；旧回调不能覆盖新一次执行。

## 运行记录与历史

agents 详情提供“活动 / 排队 / 已结束 / 全部”筛选。默认集合与状态栏当前主会话可见集合一致；明确切到 workspace 范围时可查其他会话的记录，不转移归属或混用通知。已结束包括成功完成、失败、手动停止和被运行限制中止，不能把这些状态统一标为成功。

每项展示 agent ID、名称/类型、任务摘要、ownerSession/parentAgent、本次执行标识、状态、开始/结束时间、运行耗时、用量、结果摘要与错误；完整输入、assistant 回复和工具结果在 child transcript 中按需查看。

活动执行可以实时查看；已结束执行仍可以读取结果并打开同一个原生消息查看器，保留 Markdown、代码块、thinking 和工具调用/结果折叠。关闭查看器只退出阅读。详细渲染规则继续维护在 [agents](agents.md)，不另建文本版历史渲染器。

复用 Pi SessionManager 与上游 subagents:record 的会话条目、child session 文件引用，避免另建一套会话数据库。默认保存完整 child session 和最终记录；内存对象释放后仍能通过引用查历史。主动选择不持久化的 agent 明确标记历史范围，不能承诺 Pi 退出后还能查看未保存的 transcript。

历史不因面板折叠、完成通知已读或运行数量归零而删除。列表和模型结果读取默认返回摘要，完整结果与 transcript 按需分页/滚动；长时间没有被查看的内存对象可以释放，保存的会话仍可打开。

agent ID 用于稳定引用可恢复的会话；同一 agent 同时只保留一个未结算执行，每次执行使用独立执行标识或框架已有运行代次。恢复会话开始新一次执行，前次已结束结果仍可按记录查看；主会话条目记录对应结束位置，使历史查看不会把后来新增消息当成前次执行产物。只有明确的 resume/发送新任务动作启动模型，打开历史不隐式 resume。

耗时表示本次执行开始到结束的经过时间，包含等待用户、job 或宿主的时间，不把持久会话闲置时间累加进去。运行中按查询/可见详情更新，结束后固定；用量沿用框架与上游的既有用量账本，不在状态栏重复计算。

## 查询和控制接口

保留上游的 Agent、get_subagent_result、steer_subagent 能力；查询、查看和停止各走 AgentManager 与同一个 child 记录。工具名最终在统一注册时确定，不为同一操作再暴露多套参数。

| 入口 | 契约 |
| --- | --- |
| agents 列表 / agent_list | state? 为 active/queued/finished/all，默认 active；scope? 为 session/workspace，默认 session；cursor?/limit? 分页；返回短 ID、执行标识、状态、摘要和耗时，不附整段对话 |
| get_subagent_result | 按 agent ID 获取当前或最近执行状态/结果；按需指定执行标识查看前次结果，结果分页；已完成、失败、停止记录仍可查询 |
| agents 查看器 | 按记录打开活动或历史 child transcript，历史绑定该次执行结束位置；只有在底部自动跟随活动输出 |
| agent_stop | agent ID；默认针对当前未结算执行，可按需指定执行标识；返回实际状态和停止进度，不自动删除会话或结果 |
| steer_subagent / 显式 resume | 继续使用既有向当前执行发消息和恢复已结束会话的语义；查看历史与这些动作分开 |

get_subagent_result 的 wait 仅控制这次查询是否等待；取消查询或等待超时不停止后台 child，需要明确调用停止接口。

用户在 agents 列表或查看器选择目标后可执行“停止当前执行”。可复用上游查看器已有的 x 再 x 操作，但必须在新查看器中明确提示并同步操作说明；阅读时按 Esc 退出、关闭 overlay 或停止主 agent 当前回复不能被误当作选择了该 child 的停止动作。

## 停止与资源边界

停止请求交给 child 的 AbortController/AgentSession abort 及工具取消信号，进入停止中并等待其本次执行实际结算。仅设置 stopped 标志或发送一条“请停止”消息不作为完成停止的依据；尚未返回的工具明确显示停止中，不虚构成功。

取消尚未开始的排队项会移出队列并记录停止原因，不创建 child 执行。重复停止合并已有停止请求；已经结算的执行返回既有结果。主模型停止请求、UI 停止和 child 自身结束竞争时按运行标识结算一次，旧执行的回调不能结束恢复后的新执行。

停止某个 subagent 的当前执行同时取消它尚未结算的直属及后续嵌套 subagent 执行，保留各自历史；不停止主 agent 或同级 agent。一次控制请求能查询其下属停止是否已结算，不以父项单独改状态代替 child 清理。

child 中同步执行的工具按其取消能力停止；已经建立为独立后台 job 的对象由 JobManager 持有，不随 agent 停止自动删除或终止。agents 详情展示这些关联 job，并提供跳转后单独停止的入口。外部请求已产生的副作用不能因 abort 自动回滚。

手动停止产生明确 stopped 结果，保留部分输出与错误，不把关联任务标为 done，也不把 goal 自动改为完成。等待方收到结果后按用户指令决定后续；manager 不自行重启已停止 child。第一版不额外承诺活动 subagent 跨 Pi 进程保活，已保存历史可读取与恢复执行是不同能力。
