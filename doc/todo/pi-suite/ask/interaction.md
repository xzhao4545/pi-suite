## 4. ask：查阅聊天与回答并存

默认采用有高度上限的 inline 询问，放在输入区域；问题、选项和回答草稿不以中心弹窗遮盖聊天。

保留主终端已有的历史查阅方式。由于 SSH 客户端对滚动和按键支持不同，再提供一个内置历史查阅方式：上方是当前会话历史，下方是问题和回答；历史用与 subagent 相同的原生消息组件渲染。焦点可以在历史和回答间切换，支持滚动和搜索；切换不丢失已勾选选项、输入草稿或剩余时间。

这不依赖不存在的公共“替换主聊天区”API，也不修改 Pi 私有 chatContainer。快捷键可配置，并提供面板上的入口，避免手机必须输入复杂组合键。

保持 `ask_user` 原工具名，按 [统一工具设计](../../../finished/pi-suite/tool-design.md) 使用毫秒单位的 `timeoutMs`：

```json
{"question":"选哪种方案？"}
```

省略参数使用全局默认，例如 `120000` 毫秒，具体数值可配置。

```json
{"question":"选哪种方案？","timeoutMs":300000}
```

本次等待 5 分钟。

```json
{"question":"请确认后再继续","timeoutMs":0}
```

本次不设截止时间，直到用户回答或明确取消。0 是显式关闭超时，不能被默认值覆盖；负数等无效值直接报告参数错误。

返回状态区分 `answered`、`timed_out`、`cancelled`，同时保留旧 details 的兼容字段。超时不自动选择默认选项；依赖明确回答的工作进入 waiting_user，不能把超时当成同意。

计时从问题真正展示开始，隐藏或查看历史不会重新计时；批量询问采用统一总期限。来自多个 agent 的询问排队展示，排队时间不消耗回答期限，显示提问者。回答期间主模型等待工具结果，后台进程可继续；完成通知暂存，不能打断询问或触发额外模型轮次。
