## 3. 统一界面：先解决常驻面板挤压聊天

tasks 与 agents/jobs 的必要常驻详情统一交给一个 dock 渲染，避免各模块独立决定高度。goal 摘要及 agents/jobs 的活动数量默认通过 Pi setStatus 显示；用户选择 dock 模式时纳入同一预算，对应摘要或计数不在两个位置重复显示。详细内容按需打开；完整数据不因界面折叠而丢失。

布局根据实际终端 rows/columns 决定，不猜测设备类型，不根据 SSH 判断是否为手机。建议默认值：

| 可用终端尺寸 | 本包常驻面板 |
| --- | --- |
| 高度很小，例如低于 28 行 | 1–3 行；以任务、agent、job 汇总为主 |
| 普通高度 | 总计最多 6 行，且原则上不超过终端高度的 20% |
| 用户打开详情 | 使用可滚动详情视图；关闭后恢复压缩面板 |

回答问题时，询问面板也计入预算，tasks/agents/jobs 优先收缩到汇总。尽量为聊天保留约 60% 的终端高度；超小窗口、大输入框或其他第三方扩展占用时，退化为单行汇总。这里能约束本包的组件，不能通过公共接口强行限制其他扩展的 widget。

状态摘要也会占用终端行数：Pi 原生 footer 为全部扩展状态增加一条汇总行，安排本包 dock 时需预留；pi-starship 的整体格式可换行，实际高度由其布局决定。本包缩短摘要并允许选择显示位置，不能可靠检测第三方 footer 是否实际展示了状态。配置与验收边界见 [goal 状态栏联动](goal-status.md) 和 [公共活动数量](status.md)。

截断策略：

1. 正在执行、当前选中、失败和需要用户处理的对象优先；已完成对象默认汇总。
   任务父级和未开始子任务默认折叠，当前执行组按预算展开必要行；完成项收起，完成父级按汇总显示。全部数据仍可查询和修改。
2. 先移除次要统计字段，再缩短描述，保留状态、短 ID、关键标题和隐藏数量。
3. 使用 Pi 的可见字符宽度和 ANSI 安全截断，正确处理中文、emoji 和颜色；常驻行不自动换行。
4. 任务最多父子两级，父级标题旁保留“已完成子任务数/当前子任务数”；缩短标题和次要字段，保留完成比例，不使用递归路径或多层缩进。
5. 选择和排序保持稳定；聚合刷新，避免多个面板各自高频刷屏。

手机示意，实际字段按宽度继续缩减：

```text
任务 3/12 · 进行 1 · 阻塞 2
当前 #1 登录改造 2/4 · #8 回调验证…
```

默认状态栏另显示 `goal 运行 · agents 3 · jobs 2`，dock 不再重复这些数量；有待答 agent 时优先用“待答 agent #a2”替换当前任务行。再缩小窗口时只保留必要摘要和状态行。已结束 job/subagent 保留在可筛选历史中；详情提供输入输出/会话查看和明确的停止入口，关闭详情只退出查看。

任务计数、动态调整和折叠规则见 [两级任务管理](tasks.md)；这里统一分配总高度，避免任务列表独立展开后挤占聊天区域。
