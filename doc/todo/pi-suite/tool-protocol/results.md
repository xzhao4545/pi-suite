# 返回契约与信息保留

## 模型正文和本地详情

content 是模型决策接口，默认每个事实只表达一次；不同时回显一份 JSON、另一份相同含义的自然语言和完整原始记录。优先使用首行状态与紧凑行式结果，较复杂的结构化结果沿用已有约定，比较实际 token 后确定格式，不另造难懂缩写协议。

details 是本地渲染、控制和恢复数据，继续保留必要的真实 ID、状态、变化回执与读取元数据；完整 TaskStore/JobManager/AgentManager 仍是规范来源。模型需要的失败、问题、游标等不能只放在 details 中，因为正常 Provider 不将其作为工具输出发送。

TUI 从结构化数据进行紧凑/展开渲染；模型正文长短不影响 UI 详情、执行引用、恢复能力或规范存储。读取模型输出时不凭短摘要生成另一份模型状态。

## 各类返回的最小信息

| 调用类别 | 默认 content 必须保留 | 按需详情 |
| --- | --- | --- |
| task_list | ID、标题预览、所属组、状态、组进度；有效阻塞标记/原因摘要；范围、返回数与下一页入口 | 描述、完整依赖和执行引用通过 task_get；组计数不受筛选影响 |
| task_get | ID、完整标题、状态、父级或组进度；所请求描述、有效阻塞原因/依赖、必要执行引用 | 不铺开全清单；请求的单任务描述不因列表预算而静默裁掉 |
| task_edit | 操作、真实 ID/标题与实际变化；创建子项 ID 和输入项对应关系；受影响组进度、阻塞变化、警告或失败 | 不回显未变化字段和全任务快照；批量不得省略新建 ID、部分失败或原子提交结果 |
| job_start | ID、真实启动状态、mode；有期限时返回期限；发生提前退出/失败/关联异常时保留真实结果 | 不重复原命令、启动参数和固定 read/write 指南；attach 交接保留用户返回控制的实际内容 |
| job_list/get | ID、名称、状态、耗时；终态退出码/信号、异常、清理未确认与历史只读标记；get 增加短命令及相关任务 | get(detail) 提供完整命令、cwd、时间点、归属和监视配置，不每次列表回显 |
| job_write | ID、已发送/输入已关闭等动作、必要字节数和最新状态；失败可见 | 不回显输入正文，尤其 sensitive 输入；不把“已发送”写成程序已经处理 |
| job_stop | ID、实际终态、requested、清理结果；未确认或失败必显；级联对象 ID 与实际状态 | 不重复目标摘要；停止请求不等于全部进程确认退出 |
| agent_start/send | agent ID、准确 runId、状态及动作（创建/排队/回答/引导/恢复）；必要的结果、错误和待回答问题 | 不回显 prompt、消息正文、全部模型来源和统计；前台返回的实际结果不能仅剩状态 |
| agent_list/get | ID、runId、名称、状态、耗时；待回答/失败/限制信息；get 增加当前进度、模型/思考强度和必要执行关联 | get(detail) 查看配置来源、上下文与用量详情；历史 runs 用列表分页，完整结果/会话用 agent_read |
| job_read/agent_read | ID 与必要 runId、stream、正文；原始 offset/nextOffset、总量、截断/搜索标记与精确续读入口；失败/退出信息 | 不在每页回显完整对象；stdout 非完整且 stderr 存在时保留其入口 |
| wait/通知 | 返回原因、准确对象/执行、实际状态、pending；新完成/失败/问题/监视事件与必要结果预览 | 尚在运行项简短；同一结果不经 wait、前台返回和异步通知重复注入 |
| workflow/clone/结构化结果 | 实际 ID/执行状态、恢复或结果入口、启动部分失败；结构化输出校验状态与必要警告 | 不删用户所需结构化 payload，不截断 JSON 成不可解析的假结果 |

问题交付必须保留完整问题、选项 ID/标题、回答格式和截止信息，否则上级无法正确回答；不能只压缩成 waiting。后台执行和模型/用量详情仍可在 UI 完整查看，模型只有显式请求或决策需要时才接收大量元数据。

示意返回，具体文字与序列化以实现后的 token 测量为准：

```text
done #2 检查请求链路; #1 1/3

job_3fa1c2d0 running pipe; timeout 60s

agent_3fa1c2d0 run_4fa1c2d0 queued

job_3fa1c2d0 failed exit=1; cleanup=unconfirmed
error: permission denied
```

## 正文读取、分页与预算

不采用“一律 slice 到 N 字符”。结构性关键字段必须保留；任意日志或模型长结果无法仅靠关键词保证所有结论都被保留，因此全文要可按精确入口读取，截断必须可见。摘要不能作为输出已完整阅读或任务验证成功的证据。

沿用 runtime/read.ts 的 UTF-8 边界、原始字节 offset、搜索和 source；沿用领域输出/会话存储，不新增摘要模型、永久缓存或另一套 artifact 协议。小输出完整返回，长日志默认给有界预览和错误/退出信息；长 agent 结果通过连续分页取回，避免只给开头 500 字符却当成完整结论。

初始优化预算作为实施起点，需基线测量后验证：

- 普通单项启动/发送/停止/状态变更回执目标 1–3 行、约 512 B 内；必要错误、清理结果、长标题和问题允许超过，不能丢字段来满足预算。
- 列表默认 10 条，以约 4 KiB 作为页面预算；与条数上限共同限制，超出就按记录边界分页。ID、状态、组关系等不截断，长名称/命令预览标明缩略且可获取完整值。
- job_read/agent_read 默认 limitBytes 从 16 KiB 评估调整为 4 KiB，保留最大 64 KiB 与显式指定；元数据、截断提示和续读入口也计入评估。批量创建回执、显式单项长描述、前台实际结果和结构化 payload 按业务完整性处理，不能套用普通回执上限。
- get 默认轻量状态；detail 才展开完整命令、配置来源和执行诊断。避免普通 agent_get 每次扫描所有历史 runs 和所属 job。
- 多项创建必须返回输入序号/标题与新 ID 的准确对应关系，不让模型猜测递增 ID；不能为小预算省略一部分已创建任务。

列表 nextCursor、日志/会话 nextOffset、搜索遗漏及完整日志/结果入口必须进入 content。分页提示保留当前范围、过滤和读取方式，用最短可执行形式，不能续页后意外切回默认条件。

日志 head/key/tail 预览与连续页模式必须区分：预览 nextOffset 到末尾并不表示所有正文已呈现。显式输出遗漏区间与读取方式；若结果仍在生成，当前文件 EOF 不代表 job/agent 已结算。

## 通知、错误与效率

固定说明进入现有工具描述或统一提示；成功结果通常不重复 read/stop/wait 的完整用法。需要处理截断、失败、用户问题、历史只读或清理异常时保留有针对性的下一步。

错误缩短到稳定码、原因、对象/字段和修正入口；不得静默回退、隐藏 history 查询错误或丢失“已启动但关联失败”。原始诊断保留在既有日志与状态来源，实际提供可用读取入口才允许在模型默认正文中缩略。

wait 和 Notifications 沿用统一消费/交付归属。只有实际进入 content 的结果可以按对应语义标为已交付；正文被省略的待回答问题或未交付结算不能因本地 details 存在而清掉。进度事件与最终结果仍分别消费，agent 去重以 ID/runId 为边界。

执行时用现有读取预算与记录分页实现线性工作量；不为工具精简额外调用模型，不每次查询加载整份 transcript，不靠高频轮询反复问相同状态。
