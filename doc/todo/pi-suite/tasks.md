## 5. tasks：真正的多级任务

在现有任务模型上新增可选 `parentId`，保持原任务 ID 稳定。树层级和 `blockedBy` 依赖是两种关系，不能混用。

- 创建子任务、改变父任务、查询子树；TaskCreate/TaskUpdate/TaskList 等旧工具名保留。
- 校验父任务存在以及移动后不形成树环；依赖图继续独立处理。
- 父任务的聚合进度从后代任务计算，区别于父任务自身的验收状态。子任务完成不直接证明父任务整体通过验收。
- 完成父任务时检查未完成后代；默认不允许悄悄完成或删除整棵子树，级联操作必须明确指定。
- 任务归属、执行该任务的 agent、关联 job 使用 ID 引用；任务状态和进程状态分别管理。
- 老任务没有 parentId 时视作根任务。存储带版本，迁移可重复执行，并保留原数据备份。
- 多个 subagent 更新任务要通过同一存储入口串行提交，避免各自读改写覆盖彼此的更新。

常驻面板显示当前执行路径和聚合计数；完整任务树放到可滚动详情界面，不把整棵树常驻在聊天下方。
