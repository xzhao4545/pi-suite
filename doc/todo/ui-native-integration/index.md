# 工具外观、任务 Dock 与原生会话阅读接入

本专项登记工具外观、任务恢复与选择、Subagent 初始阅读位置、工具点击及历史滚动条六项问题。方案已整理，代码尚未实施，验收尚未执行；登记方案不代表功能完成。

## 目标与问题索引

| 编号 | 用户问题 | 目标行为 | 详细方案 |
| --- | --- | --- | --- |
| UI-1 | Suite 工具外框与 Pi 内置工具不一致 | Suite 提供正文，Pi 默认工具外壳负责外观与状态背景 | [公共工具外观](tool-shell.md) |
| UI-2 | 全部完成的任务在首次加载会话时先显示、随后消失 | 恢复完成状态不触发反馈；真实完成仍反馈 5 秒 | [任务恢复与选择](task-dock.md#ui-2-恢复基线与完成反馈) |
| UI-3 | 按左方向键选择任务后，选中项向左顶格 | 保持任务原层级、前缀与文字起始列，仅高亮和粗体强调 | [任务恢复与选择](task-dock.md#ui-3-选中样式不改变缩进) |
| UI-4 | 打开已结束 Subagent 时显示顶部 | 首次打开可阅读的 run 显示最后一页，往返保留阅读位置 | [原生会话阅读](transcript-reader.md#ui-4-首次定位末尾与持续跟随) |
| UI-5 | Subagent 工具内容不响应点击 | 点击到达 Pi 原生工具组件，支持单项展开与收起 | [原生会话阅读](transcript-reader.md#ui-5-接通组件鼠标事件链) |
| UI-6 | Subagent 历史没有滚动条 | 公共阅读区接入 Pi 原生布局、裁剪与滚动条 | [原生会话阅读](transcript-reader.md#ui-6-原生滚动布局与滚动条) |

用户提出的“字体放大”在本方案中采用主题高亮与粗体表达。当前 Pi TUI 没有使用逐行字号控制能力；真正的单项字号增大不纳入此次实现，不以粗体冒充字号变化，也不引入终端专用字号协议。

## 范围与边界

- 修改公共工具正文 renderer、TasksModule 恢复与反馈、Dock 选中样式、Transcript、ScrollView 与 DetailsView；领域入口沿用既有框架。
- 工具外观须同时覆盖主会话、历史回放、child 实际 renderer 与回收后的 Suite lookup。
- 原生阅读布局须覆盖 Subagent Transcript，并核查普通详情、Jobs pipe 日志、workflow 详情及 Ask History 等共享消费者；正文类型不同不应形成另一套滚动系统。
- 不修改模型工具参数、结果正文、任务存储格式、执行状态机、run 归属、通知所有权或任务完成判定。
- 不修改 Pi 原生/第三方 footer，不创建第二套终端 renderer，不重放工具执行。
- Jobs PTY 的 xterm 屏幕、输入接管与进程尺寸仍由已有终端框架管理，不以文本 ScrollView 替代二维终端屏幕。
- 保留主题角色、字面量清理、ANSI 安全宽度、代码缓存、稳定身份、消息配对及真实执行引用边界。
