# UI-4/UI-5/UI-6：原生会话定位、交互与滚动布局

## 当前状态与共同根因

- [`src/agents/viewer.ts`](../../../src/agents/viewer.ts) 仅在没有既有 reader 且 run 为 active 时调用 follow；已结束记录首次打开采用顶部默认位置。
- [`src/ui/transcript.ts`](../../../src/ui/transcript.ts) 复用 Pi 消息和工具组件，但以 `components.flatMap(component.render)` 拼接文本行，没有向实际子组件分发鼠标事件。
- [`src/ui/scroll.ts`](../../../src/ui/scroll.ts) 的 handleMouse 只处理 wheel；点击在公共滚动层就中断，无法到达 Pi 工具组件内置的结果 MouseRegion。
- 公共 ScrollView 创建原生实例时只传 `follow: 'end'`，滚动条默认 hidden；viewport 手动 updateLayout 后截取字符串行，原生滚动节点没有作为滚动区域进入宿主布局树。
- [`src/ui/details.ts`](../../../src/ui/details.ts) 手动组合正文、信息与底部栏，正文点击转交给上述公共 ScrollView。

原生工具组件已经支持点击展开，原生 ScrollView 已提供偏移、跟随、滚动条及布局能力。问题是当前框架只组合了部分显示与状态能力，没有完整接入组件树、事件链和滚动布局。

## 公共框架接入方案

### 职责划分

| 层级 | 保留或调整的职责 |
| --- | --- |
| 领域入口 showAgent 等 | 所选记录、实际 cwd、renderer lookup、业务动作、订阅及首次定位策略 |
| DetailsView / BrowserView | 阅读、编辑、搜索焦点；信息/操作区与正文布局；返回导航 |
| 公共 ScrollView | 使用原生滚动状态；提供搜索、跟随/暂停、新输出提示与内容替换接口 |
| Transcript | 消息配对、稳定组件缓存、变化消息更新与原生子组件组合 |
| Pi VStack / HStack / ScrollView | 实际分配尺寸、正文裁剪、滚动条、布局命中与组件事件坐标 |
| Pi ToolExecutionComponent | 原生工具外壳、单项展开、结果点击与对应 renderer 调用 |

### 接入要求

1. 实施前完整核对当前 Pi 的 TUI/扩展文档与布局接口，确认 fullscreen 和 inline custom overlay 的原生组合路径、可用高度、事件传播及释放契约。
2. DetailsView 以原生 VStack 组织外边界、可选标题、正文 ScrollView、底部信息、搜索/Editor 和操作栏；需要分栏的公共消费者复用 HStack。正文是剩余空间，不再由领域页面维护另一套裁剪布局。
3. 原生 ScrollView 必须实际出现在宿主可识别的布局节点中。仅把对象藏在包装器私有字段或只调用 render，不算完成接入；包装器需要按公开组合/布局能力暴露滚动区域。
4. 使用现有 readingRows 与 overlay 预算，先为标题、分隔线、信息及 Editor/按键说明分配空间，再分配正文。布局前后使用一致的实际尺寸，不能靠首次 render 的副作用生成过时布局。
5. 移除公共正文的手动 lines.slice 裁剪职责。搜索可按正文变化/宽度保存用于匹配的行数据，但只使用原生 ScrollView 的偏移与 viewportHeight，不另存可变 scrollTop。
6. 原生布局负责正文到具体子组件的坐标映射；公共焦点边界继续隔离搜索、Editor、操作栏和正文，避免重复处理同一滚轮事件或重复扣除行偏移。
7. 原生内容刷新、主题变化与工具高度变化使用注入的实际 render 请求；计时器、订阅及原生滚动条的自动隐藏资源须随视图关闭释放。
8. 如现有包装层不能表达原生布局，优先扩展公共框架能力；不在 Subagent 页内另写鼠标命中或滚动条系统。底部信息不调用 setFooter、不重建第三方 footer。

## UI-4 首次定位末尾与持续跟随

### 目标规则

| 场景 | 行为 |
| --- | --- |
| 首次打开有可阅读 transcript 的活动或终态 run | 在实际正文布局下显示最后一页 |
| 活动 run 且停在底部 | 同一消息流式增长、并发工具输出或新增消息时持续跟随 |
| 向上阅读、Home 或搜索离开底部 | 暂停跟随，保留阅读位置 |
| End 或滚动回到底部 | 恢复跟随并清除新输出提示 |
| 从 Details、Jobs、模型编辑返回 | 沿用原 reader、搜索和工具/thinking 展开状态 |
| run 由活动变为终态 | 不重建 reader，不因结算把正在阅读的用户拉到底部 |
| 切换到另一个 run | 阅读状态按 run 身份处理，不继承上一 run 的初始定位判定 |

移除首次定位所依赖的 active 条件，保留“没有既有 reader 才初始化”的边界。初始末尾位置依赖原生实际内容高度与 viewport，不用猜测行数或固定大偏移。短正文正常显示，不补出虚假的滚动位置；排队记录仍沿用既有 Task details 入口。

终态记录首次到底部与活动记录持续跟随是不同需求；不得在每次 refresh 时调用 follow 来代替首次定位。

## UI-5 接通组件鼠标事件链

### 目标方案

- Transcript 用原生 Container 或等价原生组合保留消息子组件关系，保留原来的稳定 entry 缓存与 toolCallId 配对。
- 缓存复用的消息与变化的流式消息仍只更新各自组件；不得在每次点击、时钟刷新或 resize 时重建整个 Transcript。
- 正文点击经过公共视图与原生滚动坐标映射后，到达实际 ToolExecutionComponent；其结果 MouseRegion 负责单项展开/收起。
- 点击工具正文不执行业务动作、不发送消息、不停止 run，也不改变归属；现有 `o Tools` 全部展开/收起入口保留。
- 工具展开改变内容高度时由统一布局更新，保持现有 following/paused 状态，不重新进行首次定位。
- 正文与底部输入/操作区域互不误命中；hover 不夺焦点，未处理的拖选及链接沿用 Pi 行为。
- 鼠标能力受 TUI 模式约束：fullscreen 按 Pi 标准事件验收；inline/普通终端模式不承诺宿主未提供的鼠标能力，保留完整键盘路径。

不解析渲染文本中的图标、工具标题或横线来识别点击；不保存一份独立工具行号表来代替原生组件布局。

## UI-6 原生滚动布局与滚动条

### 目标方案

- 原生 ScrollView 统一处理正文偏移、跟随、裁剪和滚动条；其布局状态由宿主真实渲染流程更新。
- 建议滚动条策略为 `auto`：内容超出 viewport 后按原生活动策略显示；如明确要求常驻，改用 `always` 并按原生规则预留一列。两者是原生选项，不新增一套绘制逻辑；默认建议尚不等于已实施配置。
- 同一公共阅读框架使用一致策略，不在每个领域页重复决定颜色与延时；优先使用可获得的宿主主题/滚动条能力。
- 内容不足一页时无需滚动；长内容的滑块位置与原生 scrollTop 一致，自动隐藏、拖动和轨道点击按所选原生策略处理。
- 预留列、换行、中文宽字符和 resize 都按原生可用内容宽度重新布局，不让滚动条覆盖正文或推挤底部信息栏。
- 搜索定位、键盘翻页、鼠标滚轮及滚动条交互共享唯一滚动状态；暂停期间新输出提示仍位于原信息区。

仅补 scrollbar 选项不能完成本项：必须验证原生滚动节点进入布局树并由宿主绘制。inline overlay 能力需按当前 Pi 实际支持验证，未支持的部分明确说明，不创建第二套终端渲染器作为回退。

## 共享消费者与保持契约

- Subagent：实际 cwd 与 child renderer 优先级、历史 lookup、底部信息、run retain/release、输入提交边界、显式整链退出。
- 普通详情与 Tasks 只读详情：安全字面量/Markdown 选择、搜索、高度预算与关闭恢复焦点。
- Jobs pipe 日志：独立 stdout/stderr 字节窗口、暂停时窗口保持、最终补读、f/End 跟随；不重新载入全部日志。
- BrowserView 详情区与 workflow 阅读：分区焦点、各项阅读位置、动作确认与底部提示。
- Ask History：消息组件与工具 renderer 共享，询问焦点、草稿和回答状态不能被阅读布局改变。
- PTY 终端：保留已有二维屏幕与进程尺寸管理，只核查共用 frame/导航边界，不将其迁入文本阅读器。
