# UI-2/UI-3：任务恢复反馈与 Dock 选中布局

## UI-2 恢复基线与完成反馈

### 当前状态与根因

[`src/tasks/index.ts`](../../../src/tasks/index.ts) 在绑定时清空 `views` / `feedback`，订阅 TaskStore 后读取初始快照。`refresh()` 将当前 done 与之前的任务状态比较，只要之前不为 done 就加入 5 秒反馈。

首次加载时，之前的视图为空，已保存的 done 与 undefined 比较，因而被当成刚完成。`rows()` 在反馈期间保留完成组，5 秒后隐藏，导致全部完成的清单在加载时短暂出现。任务数据没有变成未完成，也不是模型重复执行。

### 目标方案

1. 明确区分建立恢复基线与监听实时变化两个阶段；可扩展现有 refresh 的更新原因或绑定初始化状态，不引入新的 TaskStore。
2. 绑定开始清除该绑定的完成反馈与计时器；初始快照读取期间，订阅回调可以刷新视图，但不能生成完成反馈。
3. 初始快照完成后，以实际载入的任务状态建立基线，再进入实时变化检测。不能只跳过一次 refresh，因为初始化期间可能收到多次订阅刷新。
4. 已保存的 done 状态不加入反馈集合；在已建立基线的绑定中真正转为 done 时，继续保留 5 秒反馈。
5. feedback 与计时器属于当前绑定，异步快照、旧订阅及计时回调不得覆盖新绑定状态。沿用现有绑定/存储身份校验，不另建会话状态系统。
6. 外部 TaskStore 提交与本会话 task_edit 使用同一实时刷新规则；任务重新打开后清除不适用的反馈，随后再次完成可以产生新反馈。
7. 快照错误使用现有明确错误通知，不将失败读取伪装成成功初始化，不写回或猜测任务完成状态。

### 边界与预期行为

| 场景 | 预期 |
| --- | --- |
| 首次加载，所有组已 done | 从第一次显示开始隐藏 Tasks 分区，`/tasks` 仍可查看数据 |
| 首次加载，完成组与未完成组并存 | 按现有优先级显示未完成组，不给历史完成组重新计时 |
| 活动绑定中完成一个组 | 保留该组 5 秒反馈，计入完成组统计 |
| 最后一个组实时完成 | 反馈到期后隐藏 Tasks 分区，不删除任务数据 |
| reload、resume、fork 或树切换导致重新绑定 | 对对应清单建立恢复基线，不因载入完成状态产生反馈 |
| 外部提交或重新打开后再完成 | 在当前有效绑定中按实际状态变化处理 |

模型提醒、任务 CRUD、派生进度、assigned/local 隔离、存储格式和 `/tasks` 的默认 All 行为不变。

## UI-3 选中样式不改变缩进

### 当前状态与根因

[`src/ui/dock.ts`](../../../src/ui/dock.ts) 的普通树形行按父子关系生成前缀，选中时却直接改为 `> `。例如子任务的 `│    ` 为 5 列，选中前缀为 2 列，文字向左移动 3 列。

[`src/ui/browser-chrome.ts`](../../../src/ui/browser-chrome.ts) 的 `selectedRow()` 默认把字符串前两个字符当作标记。保留带主题 ANSI 的树形前缀后，不能继续依赖这种字符串切片，否则可能切断控制序列。

### 目标方案

1. 行结构先按树形层级生成，选中与未选中使用相同前缀、缩进和后缀预算。
2. 推荐保留完整树形前缀，对选中行仅增加 `selectedBg` 与粗体；名称、状态、指标及任务完成删除线保留各自角色。
3. 如确有箭头需求，只在已有前缀空间内等宽替换，不插入额外列、不缩短前缀。默认方案不要求新增箭头。
4. 将公共 selectedRow 的标记处理与整行高亮分开：通过明确参数处理标记或让调用方先生成可信标记，不能再假定任意文本前两个字符可安全切片。
5. 一并核查 BrowserView / SelectList 对 selectedRow 的调用，保留原生列表身份、原生选择前缀与离开列表焦点后的样式规则，不用任务特例破坏公共接口。
6. 低于 40 列的无树形布局与单行预算合并摘要仍按现有可用空间处理；在相同布局条件下，选中不能改变对象文字起始列。
7. 真实对象必须保持可见，折叠提示、必要父级、稳定 row ID、分区顺序及来源优先级规则不变。

“字体放大”采用高亮与粗体表达，不新增终端字号协议；此限制须在操作文档中明确，不声称改变了字号。
