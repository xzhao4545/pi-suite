# UX-3：公共展示文本精简

## 需求与当前实例

所有面向用户的展示文本应简洁，去掉无操作价值的重复内容。明确实例：按 ← 进入 Dock 并选择 Tasks 时，上方标题/快捷键提示不需要附加 `read only` 或 `readonly`。

当前 Dock.header 在选中只读分区时追加 ` · read only`；Tasks 本身只提供查看动作，Enter 的 `view` 已表达用途，额外权限文字没有帮助用户完成当前操作。

## 实施契约

- 移除 Tasks 选择状态的冗余只读文字，保留必要且实际可用的选择、分区切换、打开/返回提示；紧凑布局优先保留当前对象与核心动作。
- 精简通过公共 browser chrome、tool renderer、详情信息与状态摘要等既有展示层统一实施，不在各入口复制替换规则或修改协议结果来缩短文本。
- 检查 Tasks、Agents、Jobs、Subagent/Workflow 和 Ask 的标题、摘要、状态与快捷键提示；同一信息不在相邻区重复，操作说明按实际焦点和可用动作显示。
- 不将“文本精简”解释为截断用户原文、工具真实结果、错误全文或必要详情。名称、状态、计数、关键 ID、运行归属及需要执行操作的参数应仍可获得。
- 保留真正影响操作许可的只读/权限提示，例如 workspace 历史不可控制、无法发送/停止的原因；隐藏 Tasks 的冗余文字不改变 `DockSource.readOnly`、控制准入或安全边界。
- 保留终端宽度与 ANSI/中文列处理、状态色、用户标题/说明、搜索、无障碍操作和必要错误反馈；不为简短而使用无法理解的缩写。
