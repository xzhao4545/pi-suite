# T1：持久化 fork 的任务继承

## 决策与代价

用户选择只保证持久化会话 fork 的 Tasks 继承，不实现内存 fork 快照交接，也不为此新增宿主来源字段。

优点是通过原版 previousSessionFile 定位明确来源、实现和验证范围最小。代价是内存 fork 的任务自动继承不作为保证，必须明确告知用户，不能把缺失来源伪装成成功继承。

当前源码仍使用补丁新增的 header.parentSessionId；本页不是已完成迁移的声明。

## 支持范围

- 持久化源会话通过正常 fork 事件的 previousSessionFile 读取源 header，按源实际 cwd/会话 ID 定位任务存储。
- 目标使用自己会话的独立清单。不能复用父 TaskStore 作为目标可写存储，也不能把任务继承变成执行控制权继承。
- new 独立创建；resume/reload 复用本会话数据；tree 按原有绑定契约处理，不借机改变 Goal 或 Pi 的历史行为。
- 普通内存任务及其 reload 复用保留。T1 只限定 fork 后的自动继承，不取消内存会话、子代理私有任务或 scope:assigned。
- 不读取新增 parentSessionId，不引入全局“最近源快照”，不把内存会话偷偷写入 JSONL 或任务文件。

内存 fork 不应被笼统包装成“复制清单成功”。目标按独立任务作用域处理，并明确提示未自动继承旧任务；不删除源任务数据，也不承诺原版内存源会话一定可再次切回。是否允许 Pi 自身 fork 由 Pi 原有能力决定，不能将 Tasks 的限制自行扩展为禁止整个 fork。

## 数据和执行边界

复制使用完整 TaskStore 快照，不根据当前可见行重建：

- 保留 nextId、每组 nextChild、组/子任务 ID、依赖、状态和已有领域字段。
- 即使清单为空但编号曾分配，也保留计数器，不能从 1 重新编号。
- 已使用过的目标清单不重复播种，不能覆盖目标后来编辑。
- 父/子清单修改相互独立，恢复快照不触发真实完成反馈。
- 执行捕获的分配任务、job 引用、owner 和通知仍归原清单/源会话，不迁移进程、重执行工具或重新关联执行。
- child 与嵌套 child 保留各自私有 TaskStore；scope:assigned 继续只访问准入时捕获的直接父清单。

存储继续复用既有 TaskStore 和 JsonStore 的锁内重读、复制、原子提交与订阅。源不可读、损坏或播种失败时明确报告，不静默改为新空清单，也不恢复另一工作区数据。

## 验收与任务列表

- [ ] 获得实施授权后替换源定位，并移除 parentSessionId 生产依赖。
- [ ] 持久源 fork 保留状态、依赖和完整计数器；空清单也不重置编号。
- [ ] 目标编辑不改变源，目标再次绑定不重复播种；resume/reload 保留各自结果。
- [ ] 源不可读或损坏明确报错，不覆盖错误数据、不静默宣称继承成功。
- [ ] 内存 fork 明确显示不自动继承的限制，不落盘、不复用源作为目标可写清单。
- [ ] 验证普通内存任务、child 私有清单和 scope:assigned 不被删除或转移。
- [ ] 验证旧执行/通知归属、恢复无反馈与真实完成 5 秒反馈不变。
- [ ] 实施后更新存储/操作文档；不提前把 current 中现有内存 fork 行为改成迁移已完成。
