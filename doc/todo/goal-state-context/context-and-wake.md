# 模型上下文与唤醒

[返回专项](index.md)

## 稳定目标说明

将请求专用 `pi-suite:goal-context` 替换为真正进入宿主会话历史的稳定目标说明。创建目标、修改目标、所选历史缺少当前目标说明或压缩后需要重建时，才追加必要消息；正常工具请求不重新生成、移动或替换它。

模型需要看到的内容包括精确 goalId、目标 revision、完整目标正文及必要的执行规则。完成审计、等待/阻塞和用户授权规则与现有工具描述协调去重，只在一个明确位置定义各项规则；不得删除风险边界，也不能把全部说明移到每请求变化的系统 head。

- 模型历史中的目标说明、工具结果和简短控制事件不是 Goal 状态快照，不参与状态恢复。
- 当前 Store 是目标和许可的唯一来源；历史旧目标、旧合同、旧暂停文字不能恢复目标或授予权限。
- 同会话切换到旧分支时，若该分支携带过时目标或许可，追加当前目标/必要控制说明，明确覆盖旧语义；不把整个历史投影反复重写为当前状态。
- 使用 Pi 公开消息和边界入口进行一次交付，并复用目标 ID/revision/控制代次关联。不要在 `context_with_system` 每请求临时添加再移除同一条消息。
- 说明的交付状态只作为模型上下文的派生信息，不建立第二份可恢复 Goal 状态。

## 稀疏控制与字段精简

仅在模型下一次实际工作需要知道语义变化时追加短控制事件，例如目标 revision 变化、执行/仅结案模式变化、恢复或必要等待解除。pause/clear 本身不为通知模型而启动新请求；下一次被接纳运行在其正常启动边界接收必要说明。

`usedTokens`、`turns`、`elapsedMs` 默认只留在当前状态文件与 UI，不每请求发送。预算设置/变化按需要提示，预算硬限制仍在 Manager；等待对象通过 `goal_wait` 结果和真实唤醒事件提供；进度、错误和暂停诊断只在接续或审计需要时提供，不重复序列化整个状态。

控制事件只保存最少工作语义，不复制完整状态字段或恢复前状态。最新有效事件覆盖历史语义，但工具依然校验当前 Store 和请求归属；消息文字不能反向授予执行权限。

目标正文最长等既有接口边界保持，不静默截断；长需求引用正式文档。不要通过短化 ID、移除审计要求或默认代填错误 goalId 降低输入。

## 正常自动续跑的唯一触发边界

普通短续跑消息仅在以下条件全部满足时发送一次：

1. 当前 Goal 为 active、automatic=true、未完成，且本轮仍拥有当前修订和控制许可。
2. 模型自然结束本次工作，宿主到达最终可动作边界，而不是仅收到一次工具响应或 `agent_end`。
3. 没有后续工具调用、宿主重试/压缩恢复、前序扩展继续提案或待处理消息。
4. 不处于 Goal 用户/外部等待，且没有预算、取消、暂停或自动停跑条件。

继续沿用 `agent_before_settle` 的协调顺序及稳定 `goal:<goalId>` 请求 ID。通知尚未送达时按 ID 合并，只有实际交付才计算 Goal 自动轮；不能把每个模型响应、请求尝试、UI tick 或每条事件当成一个自动轮。

首次创建、显式 resume、被安排的等待条件解除是独立的启动/恢复来源。它们仍走同一调度器；已有真实事件足以触发工作时不另加 Goal 继续正文，没有可交付事件时才使用固定短唤醒。已运行的幂等 resume 不排队第二个模型请求。

不增加工具调用后的提醒、周期性“继续”、定时模型状态轮询或每轮 Goal 查询工具。

## 统一通知与 Tasks reminder

扩展 `src/runtime/notifications.ts` 的现有批次/来源协议，使触发原因、交付回调和最小正文能够统一协调。必要时区分“Goal 自动轮交付元数据”与“是否需要独立控制文本”，但不要在 Goal 中另建队列或旁路发送。

- 真实 job/agent/workflow 结果、提问、monitor 和 hands-free 更新保持身份与来源；混合批次的交付回调只执行一次。
- 纯 Goal 控制文本仍可隐藏 UI，隐藏不等于省略模型输入；已经送入历史的内容保持稳定。
- 停止每请求删除历史旧 Goal 控制片段。通过短正文、稀疏交付和正常压缩控制体积，而不是破坏历史前缀。
- 进入暂停、完成、clear、换目标或撤销绑定时取消未送达的旧请求，不通过重写已送达历史实现取消。
- `goal_wait` 等待指定对象期间保留现有准入：无关结果排队，指定对象全部结算、期限、相关 monitor/update 或直接 child 提问等按原语义恢复。
- Tasks reminder 使用同一缓存友好交付路径，保留提醒开关、任务实际进度和 generation 校验，不再作为仅本请求存在的临时尾部消息。频率由真实需要和现有规则决定，不提高提醒频率。
- 较长结果通知以状态、关键错误及读取引用为正文；完整日志/结果留在原 job/agent 读取能力内，不能丢失证据或另建历史存储。不要把目标、全部任务或完整日志再塞进 Goal 合同。

## 压缩与上下文体积

正常工作窗口内只追加少量必要说明/事件，不回溯改写已发送历史。Goal 自身的完整状态只占一个当前状态文件；模型历史只积累必要工作内容和稀疏控制，不每响应复制完整状态。

自然压缩可以归并旧目标说明与控制事件。压缩后的当前目标锚点必须来自 Store，不依赖模型摘要恢复权限；完成重建后下一次请求复用同一份已交付消息，不再次创建请求专用合同。

不为 Goal 另起模型摘要请求或频繁强制 compact。合法压缩、选择不同历史、修改目标、切换模型/凭据及缓存过期可能导致缓存重建；“不破坏缓存”限定为 Goal/提醒在正常窗口不主动破坏稳定前缀，不承诺所有接入的生产命中率。

## 不变的 Goal 效果

执行/仅结案权限、旧请求拒绝、精确 ID、完整原目标审计、幂等完成、外部阻塞规则、真实等待、预算、取消及五轮自动停跑保持。被改动目标的在途计量不得授予新目标执行权，skipped/timed_out/cancelled 不转成危险操作同意。

普通未完成工作仍应推进，不能用 wait/block 替代；纯文字推理和活动摘要的现有边界不因精简提示而放宽。插件的归属校验不是事实验收，不能宣称仅凭非空 summary 或模型声明已自动证明全部需求完成。
