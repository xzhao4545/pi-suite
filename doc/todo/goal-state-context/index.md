# Goal 单一当前状态与缓存友好上下文

状态：待实施。当前实现仍以 [Goal 当前文档](../../current/goal/index.md) 为准；本专项只定义待实现的目标、设计与验收，不改变运行中的会话。

## 目标与范围

- 每个主会话仅保存一份当前 Goal 状态，原子覆盖更新，不保存状态版本、完整历史快照或计量增量日志。
- 历史分支切换不回滚项目文件，因此同一会话所有分支共用当前 Goal；不得根据旧分支恢复目标、进度、用量或执行许可。
- 保留完整目标范围、执行归属、暂停/恢复、等待、预算、取消、自动停跑及完成审计能力。
- 正常模型请求保持已发送的历史前缀，只追加必要内容；不再每请求替换尾部 Goal 合同或删除历史控制片段。
- 正常自动续跑只在模型自然结束、Goal 仍可执行且未完成、宿主没有其他继续工作时请求一次；不增加工具调用后的提醒、定时提醒或等待轮询。
- Goal 状态、模型上下文与 UI 展示分别承担持久控制、工作说明与可视反馈；模型历史不作为状态恢复来源。

## 当前问题与已验证边界

`GoalManager.messageEnd()` 每个 assistant 响应更新用量和次数后保存完整 `pi-suite:goal` 快照；快照不直接进入模型上下文，但会重复占用会话存储。clear 追加空快照，模型压缩不物理删除原始 JSONL。

`context_with_system` 每请求生成最新请求专用 Goal 合同，上一份合同不进入后续历史；`Notifications.project()` 只保留最近一份 Goal 控制信号；Tasks reminder 也是请求专用消息。这些投影均可能改变前次请求的历史。

同一模型、缓存键和上游凭据的受控验证中：重复请求命中约 99.96%，移除上一份尾部合同后命中 0%，保留旧合同再追加相同新消息恢复约 99.19%。这是已验证接入的直接诱因，不证明所有 Responses 服务采用相同缓存算法，也不证明其内部模型或协议转换方式。

## 约束与非目标

- 仅使用 Pi 扩展公开生命周期、消息和会话读取能力；不修改宿主、不包装 Provider adapter、不改全局网络函数。
- 存储复用 `src/runtime/json-store.ts`，通知与上下文扩展现有公共框架，不建立第二套状态源、调度器、计量账本或缓存管理服务。
- 不通过截断目标正文、缩小原始要求、取消审计或放宽工具归属来降低输入。
- 不增加自动模型状态轮询、每请求工具集合切换或每请求系统提示重建。
- 本专项不自动清理、改写或删除已有原始 JSONL，不删除用户历史分支；旧记录仅作为原始历史保留，迁移完成后不参与 Goal 恢复。
- 不扩展到项目全局单 Goal：不同主会话仍各有一份状态。普通树分支共用本会话状态；新会话与 fork 的规则见 [作用域](storage.md#作用域与唯一状态)。
- 不承诺跨缓存过期、模型/资源切换或合法压缩仍命中；保证范围是 Goal 及本专项关联提示不主动改写正常请求的稳定前缀。
