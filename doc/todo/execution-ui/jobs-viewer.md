# Jobs 直接查看与实时终端输出

## 目标

用户选中 Job 后直接进入一个查看器：上方是实际执行命令，下方是实时输出，底部是必要状态与快捷操作。不要再进入 Attach / Details / Read stream / Stop / Clear 等第二层候选菜单。

## 当前实现与根因

- Dock、`/jobs` 和 subagent 所属 Jobs 仍进入 `src/jobs/viewer.ts` 的 `jobActions()`，先通过 `ctx.ui.select()` 展示操作菜单，再分别打开详情、日志或终端；浏览器的焦点改进没有替换这一流程。
- `/jobs` 和所属 Jobs 已使用共享 BrowserView：List/Details 的 Tab 焦点、活动标题/横线、非活动选择背景、过滤/搜索/内联输入及鼠标焦点已有统一样式；稳定选择、查询和逐对象 reader 应直接保留。
- `src/jobs/log-viewer.ts` 已有有界日志字节窗口、默认 250ms 大小观察、持续跟随/暂停、新输出提示和结算后最终补读；`sanitizeText()` 后显示字面量日志，不保留终端控制语义。每次打开仍只对应一个 stream，尚未在同一 Job 查看器中切流并保留各流状态。
- `src/ui/terminal.ts` 的 TerminalView 订阅 `PtyTerminalSession.onVisualChange()`，可显示 xterm 的 ANSI 屏幕并把输入交给进程，但入口与日志查看器分离。
- PTY 输出经过 xterm 解释，可保留屏幕覆盖与颜色；pipe 的 stdout/stderr 各自直接写文件，没有合并顺序、光标或备用屏幕状态。
- 同一运行时的 `PtyTerminalSession` 已在 dispose 时保留当前 viewport 的 plain/ANSI 最后一屏，已结束 PTY 可从菜单查看；磁盘历史尚无可恢复的终端屏幕快照，不能把内存最后一屏能力视为跨进程还原。

本计划剩余工作是串联这些现有能力并新增直接查看、只读/接管模式、同屏流状态与历史快照，不重建浏览器、日志 reader 或 PTY 后端。

## 1. 统一查看入口与布局

Dock、`/jobs` 列表、subagent 所属 Jobs 列表全部调用同一个 Job 查看入口，传入稳定 ID、workspace 和只读权限。原操作菜单拆成查看器快捷动作，不另设可见动作光标。

```text
$ 实际执行命令，可展开查看多行
────────────────────────────────────
实时输出或终端屏幕
────────────────────────────────────
任务名称 · running · 32s · pty · following
 d details · c command · f follow · i input · x stop · Esc back · ←← close
```

- 顶部命令由实际 `job.command` 提供，使用[共享命令高亮](dock-tools.md#5-共享命令高亮与-suite-配置)。保持原始换行，不通过名称或工具摘要反推命令。
- 默认命令区紧凑；`c` 切换完整命令显示，长命令区按可用高度限制并可阅读，不能无限增长挤掉输出与操作栏。`d` 始终可查看未截断命令和完整字段。
- 输出、底部状态与快捷键栏有明确分隔。视口扣除实际命令、边线和操作区高度；正文填充空行，避免主会话内容穿透。
- Job 名称、状态、耗时和当前流/跟随状态在底部简洁显示；ID、cwd、归属、清理、monitor、hands-free 等详细信息放入 `d`。
- 沿用 reading/browser/details 的主题、滚动、动作和焦点框架；保留 BrowserView 已有 `▸`、活动/非活动样式、Tab 与鼠标焦点，查看器新增命令/输出/输入区复用相同角色，不创建独立终端渲染器或绕过 Manager 的输入/停止接口。
- 列表范围、状态筛选和选择身份保持现有契约。普通 Esc 从查看器返回来源列表；直接从 Dock 打开则返回主输入框。双左按统一浏览链路契约退出，不自动重开菜单或列表；该 close 传播尚未实现，需与 [统一导航](subagents-navigation.md#3-双左退出与焦点优先级) 一起接入。

## 2. 快捷操作

| 键 | 行为与条件 |
| --- | --- |
| `d` | 查看完整详情；返回后保持输出视口、流和跟随状态 |
| `c` | 展开/收起顶部命令，不改变输出源或进程 |
| `f` / End | 跟随最新输出；PTY 复用终端缓冲区跟随，日志复用 ScrollView 跟随 |
| `s` | pipe/日志模式切换可用流，沿用 stdout、stderr、input、events 等实际流契约 |
| `i` | 有权限且存在可控活动 PTY 时，在同一界面接管程序输入 |
| `Ctrl+G` | PTY 接管态交还模型控制，使用现有可配置 returnKey |
| `Ctrl+T` | PTY 接管态按现有 transferKey 发送屏幕；继续沿用现有通知与模型消息契约 |
| `Ctrl+B` | PTY 接管态按现有 detachKey 离开，Job 继续运行 |
| `x` | 允许控制且活动时停止；复用共享 ActionBar 的二次确认与实际清理结果 |
| `Delete` | 已结束、允许清理且 cleanup 已确认时删除历史；需明确确认删除范围，使用现有 clear 能力 |
| Esc / `←←` | 浏览态返回/退出；输入态规则见[统一导航](subagents-navigation.md#3-双左退出与焦点优先级) |

- 表中 Ctrl 组合表示默认值，界面提示必须读取 Suite 当前 TerminalKeys，不能写死提示而忽略用户配置。
- 保持已有按键作用域：Dock 的 `[`/`]` 切分区，BrowserView 的 `[`/`]` 切页面，JobLogView 的 `[`/`]` 读前后字节；它们不跨层同时触发，过滤/搜索/消息输入中的字符由原生输入组件消费。
- 只读对象隐藏不可用控制动作，仍可查看已有详情和输出；不同进程的历史不得伪装成可接管对象。
- Stop/Clear 的操作结果必须反映 Manager 的真实状态；pending / unconfirmed 不显示成确认成功。关闭查看器不停止进程，不删除日志。
- 控制动作应通过现有框架报告本界面中的错误或明确用户反馈，不静默切换执行/读取方式。

## 3. PTY 屏幕呈现

- 默认进入只读查看态。打开页面不会把方向键发送给程序，也不会接管输入、改变 hands-free 的控制权或触发程序操作；这是相对当前 TerminalView 的新增查看模式，不能直接使用其会将普通方向键送入 Manager.write 的输入处理作为默认浏览路径。
- 复用当前 PTY 的 `PtyTerminalSession`、xterm 缓冲区和 `renderLineFromCells()`；保留前景/背景色、文字属性、宽字符、回车覆盖、光标移动、清屏、进度条、备用屏幕及正常屏幕滚动。
- 在同一终端模型中补齐查看层需要的光标位置/可见性和视口元数据；查看滚动历史时不在错误位置绘制活动光标。
- 命令区和底部操作区不是进程屏幕的一部分；resize 只把真正的屏幕列/行数同步给终端和 PTY。尺寸没有变化时不重复 resize；活动程序按真实新尺寸重绘。
- 普通滚动停在用户选择的历史位置，返回底部恢复跟随。备用屏幕按其终端语义显示，不把全屏程序每次重绘追加成一串重复日志行。
- 通过视觉变化订阅触发 Pi 合并渲染，不在每个输出字节或每帧重建整个终端。保持有限 scrollback，不在 UI 中无限累积原始输出。
- `i` 接管后复用 Manager.write 的 user 来源、敏感输入与控制交还能力；密码等原始按键不得明文保存到输入日志。输出是否回显由程序和终端决定。
- 用户离开后解除本视图订阅，按现有规则交还控制，不 dispose 或 kill 运行中的 PTY。

文本终端能力是本专项的验收范围；图像协议等未获现有终端模型支持的内容不得宣称可以完整还原，也不能把原始终端控制序列直接输出到宿主。

## 4. Pipe 实时输出

- 复用 Pipe 已有 stdout/stderr 独立日志、字节窗口、250ms 级大小观察和结算补读，扩展同一查看器中的多流切换与逐流状态；只加载新增内容或当前有界窗口，不反复读取全量日志。
- 默认 stdout，stderr 及其他可用流通过 `s` 直接切换；每个流保存自己的阅读位置、搜索与跟随状态。无正文时显示明确空输出，不隐藏详情与导航能力。
- 暂停阅读只观察新输出/大小，不能主动跳到尾部；恢复跟随后载入当前尾部。结算时读取已经落盘的最后输出，不能因刷新计时器停止丢失最终内容。
- Pipe 保留日志的真实内容，必要的角色高亮不改变正文；不是完整终端屏幕，不解释为某个 PTY 的状态。
- 不把 stdout/stderr 的独立文件按时间猜测合并成“实际终端顺序”；不为了 UI 自动将 pipe 改成 PTY。

## 5. 已结束与历史对象

- 同 owner、终端对象仍可读取时，复用已有当前/最终 viewport 屏幕能力；若需要更完整的有界回滚缓存，在现有终端模型中扩展。退出后页面仍可滚动和查看详情，禁止向已结束程序发送输入。
- 需要跨进程恢复 PTY 最终屏幕时，扩展现有 Job 历史存储，在结算阶段保存有界终端快照及尺寸/光标信息。优先复用 xterm 的序列化能力，不另造 ANSI 回放协议，不按每帧写快照。
- 快照用于恢复保存时的最终屏幕及有限缓冲区，不意味着可以重现进程过去的所有画面或运行时序；查看历史不得重新执行命令。
- 没有终端对象或屏幕快照的记录明确标识仅可查看日志。不能只从日志尾部任意开始解析，再把缺失前文控制状态的结果标为完整屏幕。
- 只读标识、原始日志、历史清理和异常记录仍走现有 JobReader/JobControl/存储边界；清理历史时包含所属快照，不遗留永久测试产物。

## 验收

- 三个入口选中 Job 后均直接看到命令和输出，没有第二层操作候选菜单；返回后保留来源列表状态，无残留选中标记。现有 Tab/过滤/搜索/鼠标焦点样式不退化，Dock 分区和日志字节快捷键不串层。
- 用真实 PTY 程序验证彩色文本、回车进度条、清屏、光标移动、备用屏幕、中文、resize、停止和最终屏幕；输出不是原始控制码或重复重绘文本。
- 用真实 pipe 验证 stdout/stderr、长日志、多行/UTF-8 增量、暂停/恢复跟随、最终输出和只读历史；流切换不丢各自阅读状态，不伪造合并顺序。
- 默认查看无输入副作用；接管、交还、发送屏幕和离开使用当前配置，敏感输入不进入明文日志，离开后 Job 继续运行。
- 有/无历史快照分别核对显示范围，跨进程记录不出现可控提示；Stop/Clear 复核实际生命周期与清理结果。
- 大量输出时视口、缓存与 scrollback 有界；查看器关闭后没有遗留的轮询、订阅或进程控制。
