# Pi 退出清理与保活范围决策

原评估目标：在明确需要重新 attach 时评估独立 supervisor。

范围已确认：Pi 退出后，原来运行的任务与 PTY 终止；保活仅覆盖同一 Pi 进程内的 reload 与会话操作，不实施独立 supervisor 或跨 Pi 进程重新 attach。现有退出清理行为符合该要求，平台验证范围见 [执行任务](../../../current/jobs/index.md#结算与停止) 与 [当前验证](../../../current/validation.md)。下方保留原评估背景，不作为实施计划。

影响范围：进程所有权、控制通道、PTY 句柄、终端重放和版本协议。

约束：这是后续可选能力；保存 PID/JSON 不等于恢复终端，系统重启后的重执行不等于继续原任务。

相关当前文档：[项目当前状态](../../../current/index.md)。

### 6.2 Pi 退出后继续运行是下一层能力

写 JSON 或记录 PID 只能保留历史，不能恢复已经丢失的 PTY 句柄。若需要 Pi 退出、重启或 SSH 断开导致 Pi 进程结束后仍能重新 attach，需要独立 supervisor 持有进程和终端；Pi 只是客户端。

建议这作为第二阶段的可选 persistent 模式。Linux 可评估 tmux 后端；跨 Windows/Linux 的统一方案则需要独立进程服务、控制通道、终端重放和版本协议，实施成本明显更高。操作系统重启后重新执行命令属于另一种策略，不能称为继续原任务。
