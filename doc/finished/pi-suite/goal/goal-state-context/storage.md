# 单一状态存储与归属

[返回专项](index.md)

## 作用域与唯一状态

Goal 的权威状态按 `getAgentDir()` 与主会话 ID 隔离，不按当前叶子、分支 ID 或 cwd 选择。建议统一路径为 `<getAgentDir()>/pi-suite/goals/<sessionId>/state.json`，由公共路径入口生成与校验；不同会话不平摊在一个目录下。无持久会话的 SDK 场景只使用该会话内存状态，不创建虚假的跨会话持久目标。

- 同一主会话的 tree 切换始终读取同一份当前状态，目标正文、修订号、用量、进度和暂停许可不回滚。
- reload/resume 同一会话使用同一状态；仅重建运行绑定，不从历史消息获得执行权。
- new/fork 产生新会话 ID，默认没有 Goal，不因复制会话历史自动继承目标或执行许可；本专项不增加隐式目标克隆。
- 切换到其他主会话绑定其自身状态。child 不继承父 Goal 的控制权，也不为父目标创建第二份状态。
- 一个会话只保留一个状态文件；替换目标覆盖当前 Goal，不生成按 goalId 命名的状态历史。

状态文件包含 schema 版本、会话归属、必要的单调控制代次及 `goal`。`goal` 保留现有目标、权限、预算、计量、等待、进度、错误和完成字段；具体字段可在实施时去除冗余，但不得削弱语义。

## 覆盖更新与清除

复用 JsonStore 的串行操作、文件锁、锁内重读、复制后修改及原子替换。只在实际状态变化时更新；UI 时钟和重复无变化的命令不写文件。写入产生的临时文件及锁必须按公共机制回收，不长期保留备份或历史副本。

- assistant 响应计量更新当前文件中的累计字段，不追加完整快照、计量 delta 或独立账本。
- 统计变化立即更新内存/UI；需要持久化的事件应通过可等待的宿主边界完成写入，不能用后台不受控保存制造成功假象。
- 创建、编辑、暂停、恢复、等待、完成、退出等修改走同一 Store；操作成功反馈不得先于必要的持久化提交。
- clear 原子写入 `goal: null` 的极小空状态，不保存被清除目标。这份空状态仍是当前状态，用于明确“已经清除”，防止再次从旧 JSONL 导入目标。
- 持久读取缺失应返回实际缺失/空状态，不能把 JsonStore 内存中的旧 Goal 当成文件现状；如公共框架当前缺失语义不足，扩展框架能力而非在 Goal 另造文件系统。
- 无效 JSON、schema、读取、锁和保存错误明确上报，不从历史快照静默回退，不覆盖损坏数据。必要写入失败时撤销本轮自动调度/成功反馈，保留可诊断错误。

崩溃恢复读取最后一个完整原子提交；不得接受半文件或宣称未完成写入已经提交。不为追求跨宿主 transcript 与状态文件的原子事务另建 WAL、增量日志或事务子系统。

## 运行归属与并发

保留目标 ID、正文 revision、会话 Binding、请求 AbortSignal 和控制代次校验；权限以 Store 的当前状态和所属运行共同判定，不由模型消息授予。

JsonStore 的锁只能保证文件提交串行，不能使旧内存快照成为合法当前值。因此领域修改必须在锁内检查当前 goalId、revision 和控制代次，并基于锁内最新状态更新，禁止整个旧对象覆盖。

- 新的 pause/clear/edit/replace/resume 不得被旧请求结算或迟到保存回滚。
- 同一目标的在途响应计量仍按现有归属规则计入累计用量；不得因此恢复被暂停目标，也不得计入已替换的新目标。
- 同一会话被多个宿主访问时，复用 Store 的订阅/刷新能力感知外部变更，变更后撤销过期运行许可；不另建锁或租约框架。
- tree 切换撤销出站 Binding、期限和待交付控制，不把出站旧内存保存到入站状态；重绑后以当前状态重新判断是否可调度。
- 绑定或读取不会自动改变 Goal 生命周期。冷启动、退出、显式暂停和现有可恢复取消的许可语义仍按 [当前生命周期](../../../../current/goal/lifecycle.md) 保留。

## 一次性导入与原始历史

存在新状态文件时只读新状态，包括 `goal: null`，不再扫描旧 Goal 快照恢复目标。迁移与 clear 使用同一文件竞争边界，避免缺失检查之后导入覆盖较新的状态。

首次迁移可通过宿主公开 `getEntries()` 读取旧 `pi-suite:goal` 条目，并选择该会话物理追加顺序最新的有效状态，而非所选历史分支最后一份状态。版本迁移只在导入边界运行；矛盾或损坏的最新记录应报告错误，不能选择更早的成功快照掩盖问题。

导入只写一份当前状态，保留 ID、修订、累计用量、进度、完成与暂停证据；冷启动未完成目标仍要求显式恢复。确认没有旧记录时写当前空状态，明确完成迁移。新状态提交失败不得标记迁移成功。

旧 Goal 快照与恢复回执保留在原始 JSONL 中，但不再是 Goal 的状态源，new/fork 也不得通过它们重新创建目标。不要自动改写 parentId、compaction、context_edit 或删除旧会话条目；历史文件物理瘦身不属于本专项的完成门。

## UI 与查看

`/goal status`、Dock 与状态栏都读取当前 Store/Manager 视图。查看历史分支时明确展示的是当前 Goal，而不是该分支时刻的 Goal。

恢复回执只保留简短结果或 UI 提示，不再复制恢复前的完整 Goal、预算、进度与诊断；完整信息统一在当前 Goal 详情查看。原始历史 renderer 只读展示已有条目，不将展示数据恢复成状态，不为当前实现新增历史状态浏览功能。
