# 命令结构高亮与语法配色优化

## 状态与目标

命令结构识别与语法配色已实施，类型检查、相关契约与官方 CLI 自动终端验证通过，用户已确认实际预览的配色可接受。以下保留实施前根因与详细设计；稳定实现维护在 [命令结构高亮](../../../current/ui/command-highlighting.md) 和 [主题](../../../current/ui/themes.md)。

本专项不将预览终端的输入／离开异常认定为已修复；tmux 的 Ctrl+B 前缀冲突已通过默认离开键 Ctrl+] 避开，底部提示与嵌套预览输入链另行处理。

目标是改善 Bash／PowerShell 命令的可读性：让用户快速区分执行程序、选项、变量、字符串与管道／重定向关系，而不是仅让字符串有颜色。采用“命令结构识别 + 分层配色”的组合方案，保持普通参数与路径低视觉权重，不追求每个词都使用不同颜色。

用户消息背景 `#323232` 属于独立调整，不纳入本专项的功能实施；语法配色不得改变用户消息、工具状态面板、Dock 或终端默认前景／背景。

## 实施前状态与问题根因

### 共用渲染链

- [command.ts](../../../../src/ui/rendering/command.ts) 的 `CodeComponent` 先清理不可信文本、展开制表符，再调用 Pi `highlightCode(code, language)`，通过原生 `Text` 进行宽度布局。
- `commandComponent(command, shell, theme)` 提供 Jobs 与 Suite 命令字段的统一入口。
- [builtin-command.ts](../../../../src/ui/rendering/builtin-command.ts) 装饰原生模型 Bash／PowerShell 的 `renderCall`，命令当前同样由 `CodeComponent` 渲染；原生计时、调用诊断、结果与工具外壳继续由 Pi 维护。
- [tool-render.ts](../../../../src/ui/tool-render.ts) 的 `ToolCode` 与 `ToolCommand` 共用代码组件；工具展开按行索引保留组件，更新时调用 `setSource`。
- [Jobs 查看器](../../../../src/jobs/viewer/component.ts) 的顶部命令与 [Jobs 工具](../../../../src/jobs/render.ts) 的展开命令复用共享入口。主会话、child 与历史 Transcript 使用统一登记的 renderer。
- 组件已有源码、语言、主题、宽度及可信前后缀缓存。Pi 提供 live Theme proxy，主题对象身份本身不能证明配色未改变。

共享组件与原生工具组合边界合理，问题不在框架缺失，不重做工具容器或为不同页面分别实现高亮。

### Bash 的识别覆盖不足与上下文误判

当前仓库的官方 Pi 1.5.0 依赖实际使用 `highlight.js` 10.7.3。其 Bash grammar 主要覆盖脚本关键字、内置命令、字符串、变量、注释等，并不提供完整的命令行词法角色识别。

使用当前 `oh-my-pi` 主题核对源码生成的 scope 与 ANSI，得到以下现状：

| 输入 | 当前识别结果 | 问题 |
| --- | --- | --- |
| `rg -n "userMessageBg" src/ themes/ \| head -20` | 只有字符串有语法着色 | 外部程序、选项与管道符未识别 |
| `FOO=bar node scripts/build.js --mode=production > build.log 2>&1` | 整条没有语法着色 | 环境赋值、程序、选项与重定向均未形成角色 |
| `pnpm exec tsc --noEmit && git diff --stat` | `exec` 与 `stat` 被识别成内置命令 | `--stat` 中的 `stat` 被误染，词表匹配缺少命令上下文 |
| `echo "$HOME"; if test -f ./package.json; then cat ./package.json; fi` | 内置命令、控制关键字、字符串和变量能识别 | 变量颜色与正文相同，外部程序和结构符号仍欠缺 |
| `Get-ChildItem -Path ./src -Recurse \| Select-String -Pattern "theme"` | PowerShell 可识别 cmdlet、命名参数及字符串 | 覆盖优于 Bash，但管道与不同角色仍需统一层次 |

以上证明的是当前语法分类与 ANSI 输出，不是实体终端的人工视觉验收。实施时应复核实际依赖版本，不通过升级依赖或宿主来替代根因修复。

### 主题颜色重复

[oh-my-pi.json](../../../../themes/oh-my-pi.json) 当前将 `syntaxVariable` 与正文均映射到 `brightAluminum`（`#e8ecf4`）；变量即使被识别，仍接近白色。`syntaxKeyword`、`syntaxType`、`syntaxOperator` 共用电蓝色；字符串使用金色，因此字符串成为最明显的视觉区别。

未识别的文本通常没有语法前景 ANSI，显示为所在终端／容器的默认前景。修改 `syntax*` 只能改善已识别角色，不能使未识别的命令、参数或符号自动获得颜色。

### 现有测试的局限

[tool-render.test.ts](../../../../tests/runtime/tool-render.test.ts) 验证了共享组件与 Pi 原生 `highlightCode` 输出一致，以及缓存、宽度、清理和原生调用组合等契约。这不能证明外部命令、选项与结构符号区分充分；实施后应调整命令模式的断言，普通代码模式仍保留原生高亮契约。

## 功能范围与非目标

| 范围 | 计划行为 |
| --- | --- |
| 模型 Bash／PowerShell 调用区 | 使用增强命令模式，仍由 `ui.highlightBuiltinCommands` 控制 |
| Jobs 顶部命令与 Suite `ToolCommand` | 默认使用同一命令模式，不受内置工具专用开关影响 |
| child、Ask History 与 Transcript | 通过既有 renderer 共享相同显示，不重新执行历史命令 |
| `ToolCode`、JSON 与明确语言的代码 | 保留 Pi 原生代码高亮，不因 language 为 bash/powershell 就自动进入命令模式 |
| 普通日志、任意正文、工具结果 | 保持字面量，不进行语言推测或命令识别 |
| 用户 `!`／`!!` | 保留原生 `BashExecutionComponent`，本专项不接管 |
| 第三方 `renderShell: 'self'` | 保留其显示组合，不套入第二层外壳 |

非目标：修改执行 Shell、命令内容、参数 schema、存储格式、通知、Provider、工具结果、图片、鼠标分派或布局；不建设通用 IDE 语义分析，不验证程序是否存在，不解析每种 CLI 的子命令／参数 schema，不对引号内的 Python／JavaScript 等嵌入代码猜语言。

## 统一渲染层设计

### 显式区分代码模式与命令模式

在 `src/ui/rendering/` 内扩展现有组件能力，使用明确的渲染模式区分 `ToolCode` 与 `ToolCommand`，而不是根据源码或语言猜测内容用途。

- `commandComponent`、内置模型命令装饰器和 `ToolCommand` 显式请求命令模式。
- 普通 `CodeComponent` 使用代码模式，继续调用 Pi 原生高亮。
- shell 仍显式为 bash/powershell，由调用方提供；不通过命令字符串推测 Shell。若调用方不能提供真实语言，先厘清领域来源，不扩大为其他 Shell 的支持承诺。
- `setSource` 的变更判断和缓存键纳入模式。工具展开按同一行索引从 code 切换为 command，或反向切换时，不得复用错误模式的结果。
- 保留可信 `prefix`／`suffix` 与源码分离，`$ `／`PS> `、timeout 等 UI 标记不进入 Shell 词法规则。
- 不在 Jobs、工具或 child 里另建高亮实现；原生工具组合与 `registerSuiteRenderers` 的配置归属保持不变。

### 识别器选择与技术边界

实施前优先评估现有语法引擎可复用的 grammar／token 能力。若能在统一命令模式中实现位置感知的增强 grammar，应优先复用；仅扩充内置命令词表不满足验收标准。

若现有规则不能正确区分命令位置、字符串与重定向，采用共享的、Shell 感知的词法扫描能力，并保留可复用的原生识别规则。必须先证明它能处理下文边界，不以一组全局正则代替 Shell 状态。没有必要为此引入完整 AST、WASM、外部进程或新的全局运行时；若确需新增依赖，应明确它解决的识别契约、公开 API、加载成本与维护收益。

不得导入宿主私有文件或修改 node_modules 作为产品实现。若直接使用语法库，需明确直接依赖与版本，不依赖宿主的传递依赖布局；不得修改宿主全局 Bash grammar 导致原生代码块及其他扩展被隐式替换。最终技术选择与不能可靠识别的边界需在实施记录中写明。

建议在共享层使用源码区间与角色表达识别结果，例如 `start/end/role`：区间按顺序且不重叠，未分类间隙保留普通文本；相邻同角色区间可合并。该表示只服务高亮，不扩展为业务协议或另一套主题系统。

### 文本到颜色的数据流

1. 沿用 `sanitizeText` 清理传输控制字符，并保持既有制表符展示规则。
2. 在清理后的完整源码上识别命令结构，跨逻辑行保留必要词法状态；不先按行拆散引号与 heredoc。
3. 将识别角色映射到调用方提供的 Pi Theme 原生语义项，生成可信 ANSI。
4. 拼接独立 UI 前后缀，通过现有 `Text` 处理宽度、中文、emoji 与自动换行。
5. 只将展示结果保存在组件缓存，不把 ANSI、区间或高亮模式写入 command/content/details 或历史数据。

禁止对已生成的 ANSI 字符串做正则补染，也不将 HTML／ANSI 转回普通文本后重新匹配。若复用原生 tokenizer，需保持它的词法边界，再在统一输出阶段完成角色映射。

## Shell 识别契约

### Bash

| 类别 | 识别要求 |
| --- | --- |
| 程序名 | 依据简单命令的执行位置识别外部程序与内置命令；覆盖开头、换行、`;`、`&&`、`\|\|`、管道和已识别控制结构后的命令位置；不能靠 PATH 或已知程序名单 |
| 命令前赋值 | `FOO=bar node ...` 中赋值名称与后续程序分开；赋值值不被误判为程序；引用与变量展开按自身语法处理 |
| 重定向与程序位置 | 命令前或命令间的重定向目标不是程序名，不消耗尚未出现的执行位置 |
| 选项 | 识别普通参数位置的 `-n`、`--noEmit`、`--mode=production`；`=` 后值不全染成选项；`--` 结束选项区，负数值不能简单按前导 `-` 当选项 |
| 变量 | 覆盖 `$HOME`、`${name}`、常见特殊／位置参数与双引号内展开；单引号内 `$HOME` 保持字面字符串 |
| 结构符号 | 覆盖 `\|`、`&&`、`\|\|`、`;`、常用重定向及文件描述符组合；`2>&1` 作为结构处理，不拆成互相覆盖的数字、变量或程序 |
| 字符串与转义 | 单／双引号、反斜杠转义、续行与常见 ANSI-C 引号保持正确边界；引号或转义中的 `\|`、`--flag`、`#` 不按外层结构识别 |
| 注释 | `#` 仅在符合 Shell 注释起始条件的位置进入注释，不把 `file#name` 或引号中的 `#` 截成注释 |
| 嵌套结构 | 命令替换 `$()`、反引号及分组使用独立上下文；算术展开 `$((...))` 不按简单命令位置识别；保留控制关键字与函数声明的区别 |
| heredoc | 覆盖常见 `<<EOF`、`<<'EOF'`、`<<-EOF` 的正文／结束边界；正文不作为外层命令，是否允许变量展开由分隔符引用规则决定，不猜测嵌入语言 |

`git diff`、`pnpm exec tsc` 等 CLI 内部的子命令语义不作为通用扫描器的承诺。基本验收只要求程序位置、选项与结构正确；不能为提高覆盖率把每个普通词都染成程序。封装命令的任意语义也不靠大型命令特例表补齐。

### PowerShell

保留并复用原生对 cmdlet、别名、关键字、命名参数、变量和字符串的覆盖，在命令模式中统一角色映射与结构符号显示。不能套用 Bash 的单引号、转义、注释或参数规则。

重点覆盖 `Get-ChildItem -Path ./src -Recurse | Select-String -Pattern "theme"`、双引号变量插值、反引号转义、`#`／块注释、常见重定向、here-string 以及调用运算符 `&` 的上下文。任意外部程序与显式调用要按 PowerShell 的执行位置处理，比较运算符 `-eq` 等不能当成普通命名参数。

### 流式与识别范围

命令调用的部分参数可能包含尚未闭合的引号、变量展开或 heredoc。扫描器应输出已明确的区间，并将待闭合部分保留在相应字符串／正文或未确定文本状态；不阻断显示、不改写源码、不把后续尚未到达内容当成错误命令。

正常未分类内容使用普通文本是识别契约，不是异常回退。真实实现或依赖错误不得用宽泛 try/catch 静默吞掉并伪装为成功高亮。不要新增无法到达的安全兜底；确实不能可靠分类的语法边界须明确记录，不用模糊的“完整 Shell 支持”描述。

## 主题与角色映射

只调整 `oh-my-pi` 的语法相关变量与原生 `syntax*` 映射；其他主题使用其自身相同语义项。本表是建议实施基线，最终 RGB 需结合终端与面板对比度验收。

| 命令角色 | Pi 主题项 | 建议颜色 | 作用 |
| --- | --- | --- | --- |
| 程序名／函数名 | `syntaxFunction` | `#7dcfff` 浅青蓝 | 定位执行对象，外部程序与内置命令按执行角色统一 |
| 控制关键字 | `syntaxKeyword` | `#bb9af7` 淡紫 | 与执行程序区分 |
| 命名选项 | `syntaxType` | `#e0af68` 暖金 | 突出开关名称；不新增自定义 colors 键 |
| 变量／赋值名称 | `syntaxVariable` | `#7aa2f7` 蓝色 | 让变量不再与正文共色 |
| 字符串 | `syntaxString` | `#9ece6a` 柔绿 | 标识字面内容；插值变量按变量角色显示 |
| 运算符／重定向 | `syntaxOperator` | `#89ddff` 浅青 | 明确管道与流程关系 |
| 数字／字面常量 | `syntaxNumber` | 保留暖橙方向 | 与选项名称由语法上下文区分 |
| 普通标点 | `syntaxPunctuation` | 保留次要浅灰 | 不抢占程序与结构符号的视觉层次 |
| 注释 | `syntaxComment` | 保留灰色方向 | 降低视觉权重，保证可读 |
| 普通参数／路径 | 普通文本，显式基础色需要时使用 `mdCodeBlock` | 保留浅灰 | 不猜测文件是否存在，不统一改写终端前景 |

颜色定义集中在 `vars`，`colors` 只映射 Pi 已有角色。不硬编码 ANSI/RGB 到命令识别器，不新增命令专用主题协议，不改变 `text`、`accent`、success/error 等通用 UI 角色。

`syntax*` 是共享语法角色，主题修改也影响普通代码块。这属于明确的影响范围：需观察 TypeScript／JSON 与 Bash／PowerShell 代码的效果，不能宣称配色仅作用于命令。其他主题不强制采用此 RGB；即使第三方主题将角色设为同色，也不私自覆盖用户主题。

正文与关键可读文本在相关工具面板上以至少 4.5:1 为对比度目标；结合 pending/success/error 背景、256 色近似与 truecolor 做验证。格式／ANSI 检查不代替实体终端人工观感确认。

## 缓存、性能与维护约束

- 复用组件级最近结果缓存：源码、语言、模式、主题配色与可信前后缀变化更新 ANSI；仅宽度变化只重做布局，不重复词法识别。
- 若所选识别方案依赖动态 grammar 注册，将实际 grammar 变化纳入失效判断；没有此依赖时不引入额外版本计数机制。
- 继续处理 live Theme proxy，不能只比较对象身份。自带主题与其他主题切换均不得残留旧 ANSI。
- 识别以一次扫描和必要的嵌套上下文为目标，避免重复扫描后缀、逐字符生成独立组件、大量全局正则与灾难性回溯；内存随源码／区间数量增长。
- 不做 PATH、文件存在性、磁盘读取、联网或子进程查询；主题加载与依赖初始化沿用框架能力，不在每次 render 重复初始化。
- 不建设进程级全局源码缓存；组件失效与释放沿用现有生命周期，避免长命令与敏感内容长期驻留第二套缓存。
- 文件一般控制在 500 行以内，硬上限 1000 行；按组件、识别器与角色映射拆分必要模块，不为每个词法小规则单独建文件。
- 注释重点解释词法状态、边界、缓存失效与为什么不能直接补染；无需重复代码表面含义。

## 验收方式

### 语义与文本正确性

使用上述代表命令核对源码区间／角色及最终 ANSI：

- `rg`、`head`、`node`、`pnpm`、`git` 的执行位置与选项、结构角色可区分；`--stat` 不再被当成内置命令。
- 单引号、双引号、转义、注释、命令替换、算术展开、heredoc 与 PowerShell 独有边界不被外层规则污染；流式未闭合文本仍可显示。
- 去掉可信 UI 前后缀与 ANSI 后，展示文本与既有清理／制表符规则一致；不得丢失引号、空格、换行、中文或 emoji。
- 普通 `ToolCode` 保留 Pi 原生高亮，普通日志不染色；历史 content/details 与原始命令不变。

### 集成与展示正确性

复用现有工具／组件测试组织，按明确契约分组，不为每个 token 或 RGB 建独立回归测试：

1. Bash 命令位置、选项与结构识别，包括现有误染和环境赋值。
2. 引号／嵌套／heredoc／部分输入边界，以及文本清理不改变显示语义。
3. PowerShell 原有识别保持与增强角色映射。
4. code/command 模式切换、主题／宽度缓存和中文／emoji 布局。
5. 内置原生工具组合、开关与共享消费者接入，复用已有生命周期检查。

测试条目不超过功能条目的三倍；日常验证保持五分钟以内，全量保持十分钟以内。使用既有测试与类型检查，只有牵扯共享边界的回归风险新增测试，不追加大量颜色快照。

通过官方 Pi 实际入口查看模型命令、Jobs 与 Suite 展开字段，在 40／80／120 列观察换行与分层；检查 `ui.highlightBuiltinCommands=false` 恢复原生调用区，Jobs／Suite 命令仍增强。对代表 TypeScript／JSON 代码观察共享语法色影响。说明平台、truecolor／256 色覆盖范围，不把自动终端截图或 ANSI 差异视为用户已确认“更好看”。

## 实施与验证结论

- 采用无新增依赖的共享词法扫描器与源码区间；不访问宿主私有 tokenizer、不修改全局 grammar、不对 ANSI 补染。普通 code 模式仍使用 Pi 原生高亮，显式 command 模式复用同一组件、Theme、Text 和原生工具组合。
- 执行位置、参数词连续性、表达式、引用与嵌套状态共同决定角色；Bash heredoc 先确定逻辑正文边界，再在有界正文内处理展开。PowerShell 未闭合类型与表达式不重复扫描后缀。
- 新增三个语义测试组与一个官方 CLI 共享消费者测试，调整现有模式切换、历史／child 及配置快照断言；最终全量 226/226 通过，类型检查通过。
- 官方 Pi 1.5.0 自动终端覆盖 Bash 模型调用、展开 ToolCommand 与 Jobs，在 40／80／120 列和 truecolor／256 色下核对角色、Unicode、主题切换／用户主题热重载与关闭增强后的原生历史显示。PowerShell 的词法与组件验证不代表实际 PowerShell 进程或 Windows 终端验收。
- 自带语法角色与基础代码前景在三个工具背景上的最低对比度为 truecolor 4.51:1、256 色 5.21:1。用户消息背景为 `#323232`，文字为纯白 `#ffffff`；用户确认预览配色可接受。
- 支持边界为展示层词法识别，不保证完整 AST、CLI 子命令 schema、Bash extglob／数组赋值、异常 ANSI-C 控制／无效码点分隔符或 PowerShell 完整声明／成员／泛型语义；任意极深嵌套的资源上界不作承诺。
