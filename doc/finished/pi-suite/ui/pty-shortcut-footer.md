# PTY 底部快捷键提示

状态：已完成。直接接管复用共享阅读 overlay，底部退出优先、最多两行的状态提示与反馈预算已实施；普通程序与嵌套 Pi 的输入／离开范围见下文。

## 需求与范围

用户确认在提交当前命令高亮／主题改动后，完善进入 PTY 时的底部快捷键提示。沿用 `TerminalView`、共享阅读窗口和原生组件，不新建主会话 footer、widget 或输入路由。

用户在嵌套 Pi 配色预览中报告输入／离开不顺畅，输入 `/quit` 后看似停住；当次预览随后已退出。已确认的 Ctrl+B／tmux 前缀冲突由默认 Ctrl+] 避开；其余嵌套输入问题没有完整复现或根因证据，不能由提示改动直接宣称解决。

## 根因与提示边界

- `attachJob` 直接用 `ctx.ui.custom` 替换编辑器，但 `TerminalView` 按共享阅读行数预算；原生全屏 dock 的编辑器可收缩，布局边界不一致。
- 接管态将离开键排在交还／发送屏幕之后，现有窄屏 `keyHelp` 仅保留一行；浏览态没有显式离开键，接管键还可能排在其他 action 之后。
- 错误文本替换整条帮助，导致错误发生时操作提示消失。

## 确认方案

1. 直接接管进入共享 `openReading` overlay，与 `readingRows` 的尺寸约定一致；保持通知 hold、原生焦点恢复与现有 Job ownership。
2. 接管态优先显示实际配置的离开、交还输入、发送屏幕和 Shift+↑↓ 历史；浏览态优先显示离开、Esc 返回、可用的 i 接管及历史，结束／只读时不显示输入操作。
3. 复用 `keyHint` 的按键强调与次要文字色；提示最多两行，错误／确认独立显示，不替换退出提示。
4. 先扣除标题、信息、反馈和提示栏，再确定 PTY 输出行数；提示不进入子进程屏幕、日志或传给模型的屏幕文本。
5. 仅扩展共享帮助的有界换行和 action 显示排除能力，其他消费者保留现有行为。

## 验证与完成条件

- [x] 接管／浏览／结束提示与实际键位一致，错误或确认时仍能看到退出键。
- [x] 在原有真实 PTY 契约中核对提示、光标、宽度和高度预算；保留自定义键位、输入保护、交还、发送和离开语义。
- [x] 官方 CLI 在普通／全屏模式和 40／80／120 列验证直接接管、输入消费、提示状态、离开与恢复；独立 tmux 服务器核对前缀不拦截默认退出键，不改用户服务器。
- [x] 类型检查与受影响测试通过，同步当前 UI／Jobs 操作说明与 skill，归档并独立提交。

## 实施与验证结论

- `attachJob` 统一使用 `openReading`，窗口上限与组件预算一致，保留通知 hold、输入所有权、原生焦点恢复和退出清理。提示位于真实 PTY 屏幕之外，不进入屏幕传输文本。
- `keyHelp` 允许调用方显式限定换行数，其他消费者沿用默认窄屏策略；`ActionBar` 可排除已提升到主要提示的按键显示，不改变动作派发。Job 查看器的离开键在命令区／搜索焦点下仍有效，接管态保留原生程序输入分支。
- 类型检查、原有 PTY／查看器／CLI 预设契约及新增的一项官方 CLI 场景通过，全量 227/227 通过；预设验收的默认离开字节同步为 Ctrl+]，不增加 Ctrl+B 兼容兜底。
- 官方 Pi 1.5.0、Linux、headless xterm 的普通／fullscreen 和 40／80／120 列覆盖直接接管、逐次输入消费、交还／重新接管、提示更新、离开后 job 继续、命令区焦点退出、编辑器恢复与主 Pi 正常 quit。
- 独立 tmux 3.4 的正常控制终端链路中，嵌套官方 Pi 的相同两模式、三宽度输入／交还／提示及 Ctrl+] 离开、重新浏览和主 Pi quit 通过。仅修改独立服务器；没有改变用户服务器或将自动检查当作用户实际环境确认。

## 后续边界

嵌套 Pi 自身 `/exit` 后未出现预期结束状态，以及 Suite PTY 直接运行 tmux 的输出路由差异，单独保留在 [控制终端与嵌套退出排查](../../../todo/pty-terminal-investigation.md)。不把底部提示与默认离开键可用作为这些问题已修复的证据，不把 `/quit` 当作所有子程序通用退出命令。稳定行为见 [终端交互](../../../current/ui/terminal.md) 与 [Jobs 操作](../../../current/jobs/index.md#用户操作)。
