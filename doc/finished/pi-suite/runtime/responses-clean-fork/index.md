# Responses 历史净化 fork

本专项登记用户主动执行的 Responses 会话修复命令：复制当前分支，在新副本中一次性去除旧提供商的私有重放状态，然后进入新会话；后续请求继续走正常 Provider adapter，不启用持续清理模式。

命令与功能已实现、已验证；原需求与方案保留，实施前协议根因作为历史记录。真实 SDK 命令及本地受控 adapter/传输证据见[验收结论](validation.md#验收结论与边界)，不代表外网真实账号权限、解密或中转粘性验收。

## 已确认需求

- 用户命令 `/responses fork`，直接净化并复制当前分支，不选择历史用户消息作为截断点。
- 不要求选择提供商，不弹出模型/账号选择器，不自动切换渠道；新会话继承执行命令时的当前模型与思考配置。
- 原会话及其文件保持不变，可通过原生会话入口返回。
- 保留可见消息、工具参数和真实结果，以及有效调用配对和消息语义；不重新执行工具。
- 净化只处理 fork 时已有的历史，不持续过滤 fork 后产生的新响应。
- 创建新会话身份，不继承旧响应 ID 和 WebSocket 增量续接状态。
- 命令不启动模型请求、不自动发送“继续”、不调用模型生成摘要；用户后续输入才按正常流程请求。
- 对仅有密文的上下文或无法迁移的资源依赖明确报告，不静默丢失后宣称完整修复。

## 适用范围与非目标

适用于切换提供商/账号后遇到 item 归属或加密推理验证错误，以及同一提供商的历史私有状态失效。用户可以在净化前切换渠道，也可以先净化、再通过 Pi 原生入口切换；fork 本身不承担提供商选择职责。

本专项不实现 `/responses repair` 持续 portable 策略、自动 400 修复重试、账号轮换、自动模型选择或新的会话数据库。这些不是本命令的前置依赖，也不因讨论过而视为已接纳需求。

净化后的新推理状态只能在兼容的目标服务/上游身份下正常重放；多账号中转继续轮询或故障转移到不兼容身份时，后续仍可能报错。一次性净化不能替代服务端会话粘性，也不保证消除所有 400。
