# 命令、fork 语义与生命周期

## 命令契约

用户命令：

```text
/responses fork
```

命令直接复制并净化当前叶子对应的分支，不要求选择提供商、模型、账号或历史截断点。当前配置只作为新会话正常模型配置继承，不作为净化是否执行的判断条件。已选择目标渠道后执行，或执行后再使用 Pi 原生模型切换入口，均是有效操作。

Pi 原生 `/fork` 通常从选定用户消息之前分叉，`/clone` 复制当前状态。本命令虽命名为 fork，所需语义是“包含当前叶子的完整分支副本”，不能直接调用默认 before 位置而漏掉最近工具结果或最终回答。

命令不要求当前模型必须已经属于 Responses API：允许用户先净化 Responses 历史，再选择目标模型。不需要模型请求验证权限或账号归属，也不把 API Key、账号识别或真实解密作为执行前置条件。

## 操作流程

1. 检查宿主是否空闲，并捕获源会话 ID、当前叶子、绑定代次、cwd、会话持久化规则与当前模型/thinking 配置。
2. 通过 SessionManager 的公共分支与投影能力读取有效历史，按[协议净化](sanitization.md)准备新副本并检查结构及不能安全迁移的依赖。
3. 预检完成后，通过公共会话框架构造新的会话 ID、分支结构与来源引用；所有净化仅作用于待创建副本。
4. 保留普通消息、已执行工具结果、必要系统/工具声明、有效本地摘要和相关分支状态；以命令执行时的当前模型配置作为新会话最终配置。
5. 通过 Pi 正常会话替换生命周期切入新会话；源上下文在替换后失效，后续提示使用替换会话提供的新上下文。
6. 初始化新会话的任务/goal/UI/通知绑定与 Provider 传输范围，不接续源会话中的服务端响应状态。
7. 显示简短结果及能力限制，保持 idle；用户自行输入下一条消息开始正常请求。

建议完成提示（私有状态移除句仅在净化器报告 `hadPrivateState` 时使用；无私有字段时明确提示净化数量为 0，仍创建副本）：

```text
已创建历史净化副本，并切入新会话。
原会话保持不变；当前模型配置已保留。
已清除旧 Responses 私有引用与加密推理状态。
后续请求按正常模式运行，请输入消息继续。
```

提示可包含移除的推理项、私有引用数量，不显示密文、API Key 或完整私人正文。只能在副本成功建立并完成切换后报告成功，不能把源会话直接标为已修复。

## 公共框架实施路径

- 扩展命令使用 `ExtensionCommandContext` 的会话控制入口，不从普通工具执行中修改主会话。
- 实施前的公共 `fork(entryId, { position, withSession })` 没有净化 setup 参数；设计不能假定存在可在复制前变更消息的钩子。
- 优先扩展原生 fork 的会话准备能力，让有类型的净化参与新副本构造，并保持 fork 事件及来源记录。若采用公开 `newSession({ parentSession, setup, withSession })` 准备副本，则须在公共会话层统一补足 fork 的任务播种等语义，不能误用 new 语义后在命令里复制一套领域恢复逻辑。
- SessionManager 条目为 append-only。不能直接修改 getEntries/getBranch 返回对象、使用私有 `_rewriteFile`，或对已打开 JSONL 进行字符串替换。
- “先普通 fork 再仅追加 context_edit”不是完整净化实现：原始私有字段仍在新副本的 raw history，回到 edit 之前会再次暴露。构造环节须按已解析的有效贡献产生净化副本，或使用框架提供的等价有类型复制能力。
- 原生模型/thinking、系统提示与工具声明恢复沿用公共框架；不能将历史 assistant 的来源元数据伪装为当前提供商以绕过转换规则。
- 如需宿主能力扩展，应维护在受版本管理的框架实现并说明发布依赖，不把直接修改 node_modules 当作长期方案。

实施前须完整核对当前 Pi 的 extensions、sessions、session-format、message-types 与 SDK 文档，跟进复制、会话替换、初始化和恢复相关交叉引用。

## 忙碌、取消与失败

- 默认仅允许 idle 边界执行；模型流式输出、工具执行、压缩、请求重试或会话替换期间明确提示稍后执行，不自动 abort、不排队隐式分叉。
- 准备期间如果源会话或叶子改变，停止此次命令，不用旧快照覆盖用户的新状态。
- 沿用原生 before-switch/fork 的取消契约；取消后源会话、当前模型及执行对象不变，不发送“继续”。
- 读取、净化、构造与切换错误明确显示；预检失败不创建副本，切换失败不声称成功或继续发模型请求。
- 不宣称 Pi 的会话替换天然具有事务回滚。失败后的实际当前会话与是否存在已建立副本需要按宿主真实结果报告；只清理由本次命令创建且可安全删除的未完成产物，不删除原会话或已有会话。
- 无相关私有字段时仍可按命令语义创建当前分支副本，提示净化数量为零。一次命令只创建一个副本，重复执行代表用户明确再次分叉。
- 保留原生未持久化会话的能力边界，不因修复强制改为磁盘持久化；来源无法形成持久路径时不伪造 parentSession 文件。

## 任务、goal 与执行归属

- Tasks：沿用现有 fork 完整快照播种，保留 nextId、各组 nextChild、状态与依赖；新清单独立。已捕获的 child 分配任务仍指向源清单，不因净化 fork 转移。
- Goal：可保留目标内容与进度，但新副本不得继承自动续跑或外部等待唤醒而立即启动模型。通过现有 GoalManager 的许可/暂停规则表达需要用户继续，不在命令里另建全局阻塞状态；源目标与其待处理事件不被改写。
- Child/job/workflow：运行 owner、parent/ancestor、控制句柄和任务关联保持原归属；复制历史不等于复制活执行，不自动恢复、停止或重启这些执行。
- 历史引用：可沿用正常 fork 的持久来源/只读发现能力，不伪造新会话对历史对象的控制权限。
- Notifications 与队列：源会话待投递通知、待答问题和排队输入不转为新会话 follow-up，不能在 fork 后自动消费或触发新请求。
- UI：通过正常绑定恢复 Dock、footer 与查看入口，不手动复制 widget/焦点对象，也不持有旧 ExtensionAPI 在新运行时继续操作。
