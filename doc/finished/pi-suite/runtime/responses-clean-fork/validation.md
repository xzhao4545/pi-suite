# 验收与文档同步

`/responses fork` 已实现、已验证。本页保留完整验收契约；真实 SDK 命令与本地受控 adapter/传输的通过范围见[验收结论与边界](#验收结论与边界)，不把协议分析、合成转换检查或其他专项记录冒充外网真实账号验收。

## 核心验收矩阵

| 契约 | 场景 | 通过条件 |
| --- | --- | --- |
| 命令无需提供商选择 | 同一 Provider、已切换 Provider、净化后再切换；当前模型不是 Responses | 无模型/账号/历史消息选择器，不自动切换配置；复制当前叶子，继承执行时配置 |
| 原会话不变与新副本 | 多分支、正常历史、失败轮次、已有 context edit/compaction | 源文件与分支内容不变；新会话身份独立，当前有效贡献及必要摘要正确，其他兄弟分支不混入 |
| 协议内容保留 | 消息 item ID、加密 reasoning、复合工具 ID、业务参数中 id、phase | 旧私有状态不进入新副本；普通消息和参数/结果不变，配对有效，phase 保留，业务 ID 不被误删 |
| 后续正常重放 | 净化后连续两轮，第一轮返回新的 item/加密推理状态 | 第一轮不发送旧私有状态；第二轮正常携带新兼容状态，无持续清理、无旧响应续接 |
| 生命周期与归属 | 活动 task/goal/child/job、待通知/待答问题、会话替换取消 | 任务副本独立；源执行和通知仍归原 owner；新会话无自动请求，取消不产生副作用 |
| 限制与错误 | 忙碌、源叶子变化、读写/切换失败、无字段、纯密文压缩/外部资源 | 提示真实结果，不静默降级、不循环重试、不泄露内容，不将账号轮换或其他 400 宣称已解决 |

## 针对风险的自动检查

优先复用已有 SessionManager/会话生命周期及 Suite 任务、goal、通知与历史检查；新增检查围绕跨模块协议风险组织，不为每个小字段或终端宽度创建独立条目。

1. **净化与投影**：合并覆盖 textSignature 的 id/phase、thinkingSignature 中的 reasoning、callId/itemId 配对、业务 ID 与多分支/context edit/compaction 引用。验证源对象及原始文件不被修改，原始密文不残留在新副本的历史消息字段。
2. **真实会话命令路径**：通过当前 Pi 公开命令/会话入口检查含当前叶子的复制、无选择器、当前模型配置继承、替换后新上下文、未持久化边界及取消结果。
3. **请求与传输契约**：通过实际 Responses 转换和受控服务检查第一轮净化、第二轮保留新私有状态；验证新 session 的 WebSocket 缓存与 old previous_response_id 不混用，不能只断言 session ID 变了。
4. **业务生命周期**：复用任务 fork、goal 恢复、child/job owner 与 Notifications 检查，确认无自动“继续”、无工具重执行、无执行归属转移；命令提示不会启动模型。
5. **失败与边界**：合并检查忙碌/叶子替换/无相关字段/不可迁移上下文，确保明确错误及原会话可继续访问，不增加无意义的失败重试体系。

不能仅证明“发送前滤掉了旧字段”就宣布净化 fork 完成；必须检查新会话持久历史以及 reload/resume、树导航和下一轮请求。也不能仅验证第一轮成功就宣布不会再报错，必须确认第二轮按正常方式重放新状态。

测试条目与明确功能风险对应，新增数量不超过功能条目的三倍；不对 Provider、模型、传输、平台和每种字段做完整笛卡尔组合。日常定向检查在 5 分钟内，全量在 10 分钟内，稳定后再进行必要全量验证。

## 实际操作与接口验收

- 在真实 Pi 会话中执行命令，验证无 Provider/历史消息选择器、没有自动模型调用，当前模型配置与 cwd/sessionDir 规则保持。
- 保留含工具结果和加密推理的源会话，切换渠道后净化；验证新会话第一轮不携带源私有状态，普通历史仍可用于继续工作。
- 在新会话完成一轮工具交互，再进行第二轮，验证新 item/推理状态正常重放，而不是每轮被清除。
- 通过原生 `/resume` 返回源会话，再恢复净化副本；分别检查两份历史、任务边界与 Provider 正常行为。
- 核查源会话有失败请求、模型切换、文本压缩和 context edits 时的有效贡献，不能重新引入已省略内容。
- 覆盖 SSE；WebSocket/缓存续接、Azure 或其他 Responses family 若纳入支持，逐项记录实际覆盖，不从共享转换代码推断全部通过。
- 实际账号切换与中转条件须按可获得环境验证；受控服务可证明请求结构和生命周期，但不能冒充目标账号的真实解密/权限验收。
- 新会话处于用户等待状态；源 child/job 继续由原 owner 管理，返回原会话能观察其实际状态，fork 不停止或重启执行。
- 开启 goal、存在后台通知或等待期限时，命令完成不触发自动模型响应；用户明确继续后按正常框架处理。
- 源会话无相关字段、空历史或未持久化时，行为与提示符合原生能力边界，不伪造文件引用或修复数量。
- 不可迁移资源及中转轮换账号的限制明确显示；日志和提示不包含 API Key、密文或完整私人上下文。

不要求本命令保证多账号中转后续永不出现 400；此场景应记录为能力限制，不能通过重试、固定另一个账号或暗中开启持续 portable 模式掩盖。

## 验收结论与边界

离线 frozen-lockfile 安装与最终 `pnpm typecheck` 通过；最新 `pnpm test` 全量 **218/218 通过，约 1 分钟**。Responses 专项以下七项均有真实 SDK 或真实 adapter 的受控环境证据：

1. **真实 SDK 命令**：公开命令登记与 `/responses fork` 路径通过；复制含当前叶子的分支，无提供商/账号/历史消息选择器，继承执行时模型配置，不自动发起模型请求或重新执行工具。无私有字段时仍创建副本并提示净化数量为 0；成功提示依据净化器真实 `hadPrivateState` 报告生成，已有测试覆盖，不把未净化的历史冒充已移除私有状态。
2. **持久与内存 fork**：两种 SessionManager 路径及 resume/reload 通过，净化副本身份独立，持久历史与有效贡献正确；源文件/源前缀不重写，源分支保留，普通消息、工具参数/真实结果、调用配对和 phase 保持。
3. **Goal 与业务边界**：新副本 goal 保持暂停、等待用户继续；源执行 owner 与通知归属不转移，不自动续跑或消费源队列。
4. **独立任务清单**：fork 后任务编号及后续分配相互独立，nextId/nextChild 保持；空清单也保留 nextId，不因没有现存条目重置编号。
5. **OpenAI/Azure SSE**：真实 adapter 连接本地受控 OpenAI 与 Azure Responses SSE 服务，首轮净化上下文和第二轮新状态重放通过，不凭共享转换代码推断传输成功。
6. **Codex 完整 WebSocket**：真实 adapter 的完整 WebSocket 请求与两轮请求通过；新 fork 连接独立于旧连接，不携带源 response/continuation，旧连接的续接范围不被改写。
7. **Codex cached 两轮**：cached WebSocket 两轮与独立新会话缓存范围通过；新生成 item 和 reasoning 在后续轮正常重放，没有持续清理器，也未永久关闭正常续接优化。

以上证明真实 SDK 生命周期、请求结构和本地受控传输契约，不是外网账号成功声明。没有外网账号凭据，未验证真实账号权限、加密推理解密、账号/组织切换或中转粘性；本专项不进行实体人工终端或 Windows 验收。密文、账号专属资源和多账号路由的既有能力限制保持，不保证解决所有 400。
