## 5. tasks：父任务与子任务两级管理

父任务负责分组，子任务负责执行。子任务通过 `parentId` 指向父任务，最多两层；父级进度只统计直接子任务，无需递归、树路径或层级编号。父子关系与需要保留的 `blockedBy` 依赖分别管理。

- 支持创建父任务和子任务、修改标题或说明、更新子任务状态、移动子任务、删除与查询任务；不增加第三层或模型需要手工维护的深度字段。
- 子任务的 parentId 必须指向父级，子任务不能作为其他任务的父级；同一任务清单内父子共用唯一短 ID，删除后不复用，编辑、移动、排序和折叠不改变 ID。
- 父任务标题旁固定显示 `已完成子任务数/当前子任务数`，例如 `登录改造 2/4`；计数从现有子任务派生，模型不提交或维护计数字段。
- 父级有子任务时按子任务状态汇总：全部 done 为完成，存在 doing 为执行中，其余为待完成；没有子任务时显示 `0/0` 并保持待完成。父级状态无需额外修改。
- 所有子任务完成只表示该组进度完成；需要的验收工作应列为子任务，不能用面板进度自动宣告 goal 或业务目标完成。
- 删除有子任务的父级必须明确指定 cascade；删除任务不自动终止关联的 job 或 agent，执行对象按自己的停止接口处理。
- 任务归属、执行该任务的 agent、关联 job 使用 ID 引用；任务状态和进程状态分别管理。
- 存储带版本，按两级结构保存；确有格式变更时再处理迁移与原数据备份。
- 多个 subagent 更新任务要通过同一存储入口串行提交，避免各自读改写覆盖彼此的更新。

常驻面板显示父级标题、完成比例和必要的当前执行子任务；完整两级列表放到可滚动详情界面。

## 方法与参数

模型侧只暴露两个任务工具，参数使用明确字段和短 ID，支持一次调用修改多项。第一版不同时注册多套具有相同职责的任务工具。

### task_list：查询

| 参数 | 用途 | 默认行为 |
| --- | --- | --- |
| id? | 查询一个父任务或子任务 | 不指定则查询任务列表 |
| parentId? | 查询指定父级及其子任务 | 不指定则查询所有父级 |
| includeDone? | 包含已完成任务 | 列表默认省略已完成父级和子任务 |
| detail? | 返回说明、依赖与执行关联等详情 | 默认返回短 ID、标题、状态、必要的父子关系和父级进度 |

id 与 parentId 不同时使用。按 id 查询时只返回该对象，即使已完成；单个子任务带 parentId。按 parentId 查询时始终返回指定父级，子任务默认省略已完成项，includeDone 可查看全部子任务。不指定 id/parentId 时按父级分组返回未完成父级及其未完成子任务，includeDone 可查看完整清单。列表输出中的父级进度始终按全部现存子任务计算，不能因隐藏完成项而改变总数。常驻面板的显示筛选不改变查询和存储能力。

示例：`task_list({})` 查看未完成事项，`task_list({"parentId":"1","includeDone":true})` 查看某组全部任务，`task_list({"id":"2","detail":true})` 查看单项详情。

### task_edit：批量增删改

参数为 `changes` 数组，每项只包含本次操作需要的字段：

| 字段 | 用途 |
| --- | --- |
| op | add、update 或 delete |
| id? | update/delete 的目标短 ID |
| parentId? | add 子任务或 update 移动子任务的目标父级 |
| title? | add 必填，update 时可修改标题 |
| status? | 子任务状态 todo、doing、done，创建子任务默认 todo |
| description? | 按需提供或修改额外说明 |
| children? | 创建父任务时可直接提供子任务标题数组 |
| cascade? | 删除带子任务的父级时明确设为 true |
| blockedBy? | add/update 时指定或替换依赖 ID 数组，反向 blocks 自动派生；问题边与带未完成阻塞项的执行状态更新返回警告 |

新增操作不传 parentId 时创建父级，传 parentId 时创建子任务。children 只用于新增父级，不接受嵌套子任务；已有父级的子任务通过同一批次中的 add 项动态添加。父级标题和说明可修改，status 由子任务派生，传入父级 status 时明确报错；移动只允许将子任务移至另一个父级。更新只提交变化字段，description 传空字符串可清空说明。

```json
{
  "changes": [
    {"op":"add","title":"登录改造","children":["实现接口","验证回调"]},
    {"op":"add","title":"清理构建脚本","children":["整理配置"]}
  ]
}
```

以上传给 task_edit，一次创建两组并返回分配的父子短 ID。修改已知任务时同样批量处理：

```json
{
  "changes": [
    {"op":"update","id":"2","status":"done"},
    {"op":"add","parentId":"1","title":"补充异常验证"},
    {"op":"update","id":"3","title":"验证登录回调与取消场景"},
    {"op":"delete","id":"5"}
  ]
}
```

新建父级的直接子任务使用 children 一起创建，不引入临时 ID 或批内引用协议；需要复杂说明的子任务可在取得真实 ID 后修改。修改结果只返回新建项的 ID/标题及父子关系、变更对象的 ID 和实际变化字段、删除 ID 和受影响父级进度，不重复发送全部任务与未变化的长说明。

一批 changes 按数组顺序处理，在同一存储入口校验并提交；无效目标、层级或删除操作不能造成半批生效，错误返回对应操作位置和原因。模型可以随实际情况追加、取消、改名、调整工作内容或重新打开已完成子任务，不需要用整张清单覆盖现有状态。

## 完成比例与动态调整

- 新增子任务增加总数；删除未完成子任务只减少总数，删除已完成子任务同时减少完成数和总数。
- 子任务 done 改回 todo/doing 时减少完成数，对应父级重新进入未完成显示集合。
- 子任务移动后，源父级和目标父级都重新计算进度。
- 不保留人工填写的百分比或过期计数；隐藏、折叠和搜索不参与进度计算。

## 自动折叠与显示筛选

未完成父级和已完成父级都默认折叠，只显示短 ID、缩短后的标题和完成比例；有空间时，当前执行的父级自动展开必要的 doing 子任务，其余未开始子任务仍收在父级中。模型不用操作面板折叠参数。

已完成子任务可以短暂显示完成反馈，随后从常驻子任务行收起，进度保留在父标题旁。已完成父级短暂保留后从常驻列表剔除，汇总为“已完成 N 组”；仍可通过查询或详情展开和修改。这里的剔除只改变显示，不清理数据。

当未完成父级也过多时，统一 Dock 先按选中组、当前执行、阻塞待处理、完成反馈、普通待处理组的优先级显示父行，同类以最近变更稳定排序，再按剩余预算展开相邻子行，剩余项目以数量汇总。选中组用稳定 ID 保存并显示 `>` 标记，其他 child 更新不改变选择；父级或子任务的未完成 blockedBy 提高该组优先级。长标题优先裁剪，完成比例和必要状态保留；本模块不能突破与 ask、agents、jobs、goal 共用的总高度预算。询问期间提供压缩摘要，完成数/总数、doing/blocked 均按实际子任务统计，不重复计入父级。

窄屏终端在有 3 行预算时可显示：

```text
▾ #1 登录改造 2/4
  ▶ #4 验证回调
…另 2 组未完成 · 已完成 3 组
```

用户主动进入详情后可展开父级、查看未完成或已完成项并滚动；阅读中的选中对象不会被自动折叠或完成反馈定时器突然移走。退出详情后恢复常驻压缩布局。

## 保留的上游行为

- 存储：默认按会话保存在 `<cwd>/.pi/tasks/tasks-<sessionId>.json`；`<file>.lock` 记录 pid:uuid，最多重试约 5 秒并识别陈旧锁，释放时校验令牌；每次修改在锁内重读后原子写入；文件缺少有效字段时保持当前状态不覆盖。`--no-session` 时只在内存保存。
- 依赖：blockedBy 与反向 blocks 双向维护；自引用、不存在目标和二元环在结果中警告，删除任务时清理指向它的边；列表只显示未完成的阻塞项。
- 会话：new/resume/fork 重置会话级状态；fork 以父会话清单为种子；工作区变化时重新定位存储；reload 按目标键复用清单，存活 child 保留原 TaskStore，恢复沿用稳定 agentId/taskId。
- 提醒：连续若干轮未使用任务工具时，在下一次请求注入一条任务提醒，存在 doing 子任务时缩短间隔；提醒只进入该次请求上下文，不修改工具结果，可在配置 tasks 节关闭。
- 执行关联：agent_start 的 taskId 记录执行该任务的 agent；child 结算不自动把任务标为 done，由模型或 child 通过 task_edit 更新。

不保留按轮次删除已完成任务的 auto-clear、显示排序与字形配置、上游 widget 与设置菜单；dock 显示与折叠规则见上节。
