# 存储

[返回目标管理](index.md)

## 文件与作用域

每个主会话一个状态文件：`<getAgentDir()>/pi-suite/goals/session-<sessionId>/state.json`。`sessionId` 经 `encodeURIComponent` 编码并加固定前缀，因此 SDK 自定义 ID 也不能借 `.`、`..` 或路径分隔符离开该目录。未保存到磁盘的会话只用内存中的状态。

文件内容为 `version: 1`、`sessionId`、单调递增的 `control` 和 `goal`。字段见 [目标字段](lifecycle.md#目标字段)。替换目标覆盖同一文件；clear 写入 `goal: null`，不保留被清除的目标。界面、用量与恢复都读这一份状态，没有快照集合、计量日志或权限副本。

- 同一会话的所有树分支共用目标、`revision`、用量、进度、预算与暂停状态。切换分支只撤销旧绑定、待交付的继续请求与等待，再绑定当前状态，不按所选历史恢复旧目标。
- `/new`、`/fork` 使用新的会话 ID，没有目标；复制过来的历史目标说明不授予任何权限。子代理不继承父会话的目标。

## 并发修改

使用公共 `JsonStore`（`src/runtime/json-store.ts`）：串行写入、跨进程文件锁、锁内重读、复制后修改、原子替换，以及目录监听。

- 控制操作（pause、clear、edit、replace、resume、完成、阻塞、等待）在锁内核对目标 ID、`revision`、`control` 与会话绑定后基于最新状态修改。过期的控制返回 `GOAL_STALE`，不能覆盖较新的操作。
- 状态文件被其他 Pi 进程修改后，监听发现 ID、`revision` 或 `control` 变化，撤销过期的运行与等待，不会自动授予新权限。
- 各操作在必要的写入提交后才返回成功或安排新工作。内容无变化时不写文件；界面计时只读内存中的运行片段。
- 损坏的 JSON 或 schema 不符返回 `GOAL_STORE_INVALID`，会话不符、读取、锁与写入失败也直接报告。坏文件不会被覆盖，不从历史回退，也不启动自动续跑。原子写入留下的临时文件和锁由公共机制回收。
- 文件不存在时读作未初始化，不把内存中的旧目标当作磁盘现状。

## 计量

响应用量只在会话绑定仍有效且目标 ID 未变时累加到 `usedTokens` 与 `turns`，不改生命周期。修改目标文本后，在途响应的用量照常计入；暂停后迟到的计量不能让目标恢复；替换或 clear 后不计入新目标。多个 Pi 进程的计量与控制共用同一把文件锁。

## 从旧会话条目导入

旧版本把目标快照写在会话文件的 `pi-suite:goal` 条目里。首次恢复会话且没有当前状态文件时，在同一把锁内导入一次：

1. 通过 `getEntries()` 取整个会话按追加顺序的最后一条 `pi-suite:goal`，不看当前所选分支。
2. 最后一条损坏时拒绝导入，不退回更早的有效条目。没有条目或最后一条为 `goal: null` 时写入空状态。
3. 快照 version 1 与 2 在解析时迁移到当前字段：保留 ID、`revision`、用量、耗时、进度、完成证据与暂停诊断。旧的 `failed`、`blocked`、`budget_limited`、`stopped`、`paused` 都转为 `paused` 并记录相应原因；旧的 `resumeRequired` 字段被丢弃，原因由 `kind` 决定，只有缺少更具体原因的 version 1 记录会以它推出 `permission`。
4. 写入成功后导入才算完成。已有状态文件（包括 clear 后的空状态）总是优先于会话条目。

导入后未完成的目标随冷启动暂停为 `startup`，需要 `/goal resume`。`/new`、`/fork` 不导入复制的历史。

会话文件中的旧快照、恢复条目、`parentId`、压缩与 `context_edit` 都保持原样，只作为历史显示，不是状态或权限来源。目标模块不向会话文件追加状态快照或计量条目，也不借压缩删除历史。
