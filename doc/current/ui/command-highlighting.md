# 命令结构高亮

## 入口与范围

`src/ui/rendering/command.ts` 的 `CodeComponent` 提供两种显式模式：普通 code 模式调用 Pi `highlightCode`，command 模式由 `src/ui/rendering/shell/` 的 Bash／PowerShell 扫描器产生源码区间，再用调用方提供的 Pi Theme 着色。语言不从内容猜测，扫描器不执行命令、不查 PATH 或文件、不读磁盘、不联网。

| 显示位置 | 模式与配置 |
| --- | --- |
| 模型 Bash／PowerShell 调用区 | command，由 `ui.highlightBuiltinCommands` 控制，默认 true |
| Jobs 顶部命令、Suite `ToolCommand` | command，默认增强，不受内置工具专用开关影响 |
| `ToolCode`、JSON 与明确语言的代码 | code，使用 Pi 原生高亮；language 为 bash/powershell 也不自动切换用途 |
| 普通日志、工具输出、任意正文 | 字面量，不猜测代码或命令 |
| 用户 `!`／`!!` | Pi 原生 `BashExecutionComponent` |
| 第三方 `renderShell: 'self'` | 第三方自身的显示组合 |

主会话、child、Ask History 与 Transcript 通过既有 renderer 登记复用这些规则；阅读历史不重新执行命令，不修改 command/content/details。增强内置调用区仍调用原生 `renderCall` 维护计时与诊断，原生工具外壳、结果、流式更新、截断、超时、图片和展开能力由 Pi 管理。

## Shell 词法边界

### Bash

- 根据简单命令位置区分程序与参数：覆盖开头、换行、分隔符、管道、控制结构、函数、分组与命令替换。命令前的普通环境赋值与重定向不消耗尚未出现的程序位置。
- 选项名与 `--key=value` 的值分开；`--` 结束选项区。负数按数字处理，不查询 CLI 参数 schema，也不推断 `git diff`、`pnpm exec tsc` 等内部子命令角色。
- 单／双引号、常见 ANSI-C 引号、转义、续行、变量／位置参数、`${...}`、`$()`、反引号与算术／条件表达式保持各自上下文。双引号内 `${...}` 的单引号不会抑制变量插值。
- 注释只从符合条件的词边界开始，`file#name` 和引号中的 `#` 保留字面含义。函数体和 case 的普通模式，包括可选的模式起始 `(`，与执行位置分开。
- heredoc 分隔符先进行引用移除；覆盖常见引用、ANSI-C 字面分隔符、多个文档与 `<<-` 的制表符规则。未引用文档按逻辑行处理反斜杠续行，先确定完整正文边界再在有界正文内扫描展开；引用文档保持字面字符串。正文不作为外层命令，不猜测嵌入语言。

### PowerShell

- cmdlet、别名与外部程序统一按执行位置识别；命名参数、比较运算符、变量、字面常量、类型、控制关键字和管道／调用／重定向按词法上下文区分。赋值右侧允许命令管道，命令参数中的 `=` 不切换为赋值语句。
- 完整的命令路径与普通参数路径保持一个词，`/` 与 `:` 不在参数路径中单独染为算术运算符。相邻引号片段与反引号转义空间不创建新的选项位置。
- 单引号与成对引号转义、双引号插值、反引号转义／续行、块／行注释、`$()`、分组、here-string 和常见类型边界使用 PowerShell 规则；hashtable 的普通键不作为程序名。
- `&` 接受字面路径、变量或引用程序；`--%` 后的当前物理行保持字面内容。比较运算符在表达式上下文中识别，不覆盖程序普通参数及 `--` 后的字面值。

未闭合的引号、展开、类型或正文按已经明确的词法上下文显示，不阻断流式命令，不尝试修正源码。正常未分类内容使用基础代码前景，不以异常吞噬掩盖实现失败。

扫描器是展示层词法识别，不是完整 Shell AST、语法检查或执行语义分析。Bash extglob 等模式内部复杂括号、数组赋值语义、异常 ANSI-C 控制／无效码点分隔符，以及 PowerShell 完整成员／泛型／声明语义不作为精确分类保证；没有完整语法或操作系统范围证据时不宣称支持完整 Shell。嵌套扫描沿用调用栈，不承诺任意深度恶意输入的资源上界。

## 配色与缓存

程序／函数使用 `syntaxFunction`，控制关键字使用 `syntaxKeyword`，选项／类型使用 `syntaxType`，变量使用 `syntaxVariable`，字符串使用 `syntaxString`，结构符号使用 `syntaxOperator`，数字／常量使用 `syntaxNumber`，注释使用 `syntaxComment`；普通参数与路径使用 `mdCodeBlock` 基础前景。RGB 由活动主题决定，不硬编码到扫描器，不新增主题协议。自带配色见 [主题](themes.md#语法配色)。

文本先经 `sanitizeText` 清理，再在完整源码上产生有序不重叠区间；真实制表符保留到词法识别结束，着色后按现有四空格展示规则展开。可信 `$ `／`PS> ` 与 timeout 前后缀不进入 Shell 规则，ANSI 不参与再次匹配。多行角色按逻辑行重新应用前景，再交给原生 `Text` 处理 ANSI、中文、emoji 和宽度换行。

每个组件保留最近源码的区间与布局缓存：源码、语言、用途模式变化清理区间；主题或可信前后缀变化重新着色；只变宽度时只重新布局。live Theme proxy 通过所用主题角色的 ANSI 配色指纹失效，不只比较对象身份。`ToolBody.setSource` 显式保留用途模式，同一展开行从 code 切换为 command 或反向切换时不会使用另一模式的缓存。

识别与着色保持线性扫描／区间输出；heredoc 的边界收集与有界展开为两遍线性处理。PowerShell 未闭合的嵌套类型单次向前扫描，不从每个 `[` 重试搜索完整后缀。缓存归属组件，不建设进程级源码缓存或第二套布局／业务状态。

## 使用与验证范围

修改 `ui.highlightBuiltinCommands` 后执行 `/reload`；false 恢复完整原生命令调用显示，Jobs／Suite 命令字段继续增强。包主题编辑后 `/reload`，用户主题目录的活动主题支持原生热重载，加载方式见 [主题操作](themes.md#加载与切换)。

语义检查覆盖代表命令、引用／嵌套／heredoc／流式边界、模式切换、主题缓存和文本保真。官方 Pi 1.5.0 实际 CLI 的自动终端检查覆盖 Bash 模型调用、Jobs 与 Suite 展开命令，在 40／80／120 列和 truecolor／256 色下核对颜色角色、Unicode、主题切换／用户主题热重载及配置 reload。PowerShell 有词法与组件展示检查，不将其表述为实际 PowerShell 进程或 Windows 终端验收。人工观感与自动颜色／宽度检查是不同边界。
